# `@warpgogol/tokens` — Agent Guide

Canonical `--ds-*` CSS design tokens — single source of truth for colors, typography, spacing, radius, shadows, motion, and z-index (RFC-0023).

## What lives here

| Entry point | Module | What it provides |
| --- | --- | --- |
| `@warpgogol/tokens` | `src/index.ts` | `TOKEN_NAMES` (tuple of every `--ds-*` token), `DesignToken` type, `TOKEN_NAME_SET`, `TOKEN_CATEGORIES` |
| `@warpgogol/tokens/tokens.css` | `src/tokens.css` | Raw CSS file with all `--ds-*` custom property declarations in `@layer tokens { :root { ... } }` |

## Rules for AI agents

- Do NOT declare `--ds-*` properties anywhere except this package.
- All components and apps MUST use `--ds-*` tokens instead of hardcoded values.
- Biome-specific token overrides belong in biome YAML (`packages/ontology/biomes/`) and are generated by `biome.css.generate`.
- `TOKEN_NAMES` in `src/index.ts` MUST stay in sync with `src/tokens.css`. The `tokens.catalog.sync` workspace command (in `@warpgogol/site-kernel-checks`) detects drift in both directions — tokens declared in CSS but missing from the TS catalog, and vice versa. Run `pnpm exec site-kernel run tokens.catalog.sync` to verify.
- The `@layer tokens { :root { ... } }` wrapper is REQUIRED — without it, unlayered `:root` would always win over `@layer biome.<id>`, silently defeating biome customisation (RFC-0071).

## Token categories

- **Colors** — `--ds-color-*` (primary, neutral, semantic palettes)
- **Typography** — `--ds-font-*`, `--ds-text-*`, `--ds-line-height-*`, `--ds-tracking-*`
- **Spacing** — `--ds-space-*`
- **Radius** — `--ds-radius-*`
- **Shadows** — `--ds-shadow-*`
- **Motion** — `--ds-duration-*`, `--ds-ease-*`
- **Z-index** — `--ds-z-*`

## Usage

### Import in app global styles

```css
@import "@warpgogol/tokens/tokens.css";
```

### Use in component CSS

```css
.button {
  background-color: var(--ds-color-primary-500);
  border-radius: var(--ds-radius-md);
  transition: background-color var(--ds-motion-duration-fast) ease;
}
```

### TypeScript token constants

```typescript
import { TOKEN_NAMES, TOKEN_NAME_SET } from "@warpgogol/tokens";
```

## Validation

```sh
pnpm --filter @warpgogol/tokens build:check
```
