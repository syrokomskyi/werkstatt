# ADR-0046: IMG-DELIVERY-04 page-level LCP check must skip 404.html

## Context

RFC-0830 introduced `image.delivery.validate` with three rules: IMG-DELIVERY-01 (srcset), IMG-DELIVERY-02 (compression budget), and IMG-DELIVERY-04 (LCP image optimization via `fetchpriority="high"` marker). The page-level IMG-DELIVERY-04 check requires at least one `<img>` with `fetchpriority="high"` on every page that has images. This check fires on any HTML page in `dist/client/` that contains `<img>` elements but none with `fetchpriority="high"`.

The 404 page (`src/pages/404.astro`, generated by `routes.generate`) renders the site chrome (header with logo, footer) which includes `<img>` elements, but has no content images — it is a non-content error page with `robots: noindex,follow`. The page-level IMG-DELIVERY-04 check flagged `404.html` because the chrome images (header logo, etc.) don't carry `fetchpriority="high"`, and there is no meaningful LCP content image to mark.

This surfaced during mission `warpgogol-com-m000054` close, blocking `mission.validate` with a false positive.

## Decision

The page-level IMG-DELIVERY-04 check ("at least one `fetchpriority="high"` image per page") skips `404.html`. The per-image IMG-DELIVERY-04 check (attributes on images that already have `fetchpriority="high"`) is not affected — it still runs on all pages including 404.html.

- The skip is based on the file basename: `basename !== "404.html"`.
- The skip only applies when the page has images but none have `fetchpriority="high"` — if a 404 page legitimately marks an LCP image, the per-image attribute check still validates it.

## Justification

- **404 is a non-content error page**: It has `noindex,follow` and no meaningful LCP content image. Chrome images (logo, icons) are layout elements, not LCP candidates.
- **No false negatives**: The per-image check still runs — if someone adds `fetchpriority="high"` to a 404 page image, it must still have `loading="eager"` and `decoding="async"`.
- **Minimal and explicit**: The exemption is a single basename check, not a config file or a per-page opt-out. It is easy to understand and maintain.

## Consequences

- Positive: 404 pages with chrome-only images no longer trigger false IMG-DELIVERY-04 errors.
- Positive: The per-image attribute check is unaffected — 404 pages are still held to the same standard for any image that does carry `fetchpriority="high"`.
- Negative: If a future site has a 404 page with a meaningful content image, the page-level check won't enforce marking it. This is acceptable — 404 pages are non-content error pages by convention.
- Technical debt: None — the fix is a 2-line addition in the page-level check loop.

## Evolution

This ADR documents a post-hoc fix already applied in platform 5.51.4 (commit `ecosystem.commit` by Cascade, 2026-08-13). A regression test that verifies `404.html` is exempt from the page-level IMG-DELIVERY-04 check must be added to `packages/werkstatt-site/src/checks/tests/image-delivery.test.ts` in a follow-up implementation session. The test should verify that a 404 page with images but no `fetchpriority="high"` does not produce an IMG-DELIVERY-04 error, while a non-404 page with the same content does.
