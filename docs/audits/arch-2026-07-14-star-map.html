Problem: render.ts is 289 lines mixing the manifest adapter, graph construction, SVG string generation (node/edge helpers, style constants, XML escaping), file I/O, and the public API — the SVG rendering logic is the largest chunk and has no testable seam.

Solution: Extract an SvgRenderer module that owns svgNode, svgEdge, style constants, and escapeXml; render.ts calls renderer.render(graph, positions, dimensions) and remains responsible for the adapter and file emission.

  • locality: SVG generation in one module
  • leverage: renderer testable in isolation
  • depth: render.ts interface stays narrow
