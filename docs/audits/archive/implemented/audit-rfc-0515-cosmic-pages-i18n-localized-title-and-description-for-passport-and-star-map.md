# Audit: RFC-0515

## Verdict: Needs revision

The RFC correctly identifies a real i18n inconsistency (German tagline in UK-locale cosmic page metadata), but its solution is architecturally flawed: it proposes editing generated files directly, misidentifies the governing DNA invariant (DNA-35 ≠ cosmic naming contract), and places validation logic in the wrong package. The root cause is in the `overlay.pages.generate` generator, which the RFC does not mention.

## Mechanical validation (rfc.validate)

Pass — no violations targeting RFC-0515.

## Axis A — Structural completeness

- **FAIL — Problem description is inaccurate.** The RFC states (line 84): "Their `title` and `description` frontmatter fields contain the German system tagline." The actual files show the title is `"Cosmic Passport · Website, die gefunden wird und Ihrem Betrieb gehört"` and the description is `"Release manifest for Website, die gefunden wird und Ihrem Betrieb gehört: signing keys, source provenance, star-map for audits."` The tagline is embedded as the brand name (via `brandHeadFromTagline`), not used verbatim as the entire field value. The RFC overstates the problem.

- **FAIL — "No migration needed" is wrong.** The Rollout section (line 164) says: "No migration needed: The fix is a content edit in the workpiece, not a data contract change." But the cosmic page files are **generated** (see Axis C). Content edits to generated files are overwritten on the next `overlay.pages.generate` run. This is a fundamental misunderstanding of the file ownership model.

- **Minor — Acceptance criteria are checkable but insufficient.** Criterion "DE cosmic pages remain unchanged" (line 182) is checkable, but the RFC doesn't specify what the UK localized title/description should be — only that they should be "localized." An agent implementing this would need to author Ukrainian text, which is a content decision the RFC defers without guidance.

## Axis B — DNA alignment

- **FAIL — DNA-35 is misidentified.** The RFC's `satisfies: [DNA-35]` (line 32) and Architectural fit section (line 102) state: "DNA-35 (Cosmic naming contract): Cosmic pages are part of the cosmic overlay system." But DNA-35 in `docs/architecture-dna.md` (line 155) is "`app.contract.full` as the canonical readiness signal" — the unified validation command. The cosmic naming contract is **DNA-23** (line 101). The RFC must either:
  - Change `satisfies` to `DNA-23` (the actual cosmic naming contract), or
  - Add `DNA-35` only if the RFC genuinely extends the `app.contract.full` readiness signal (it does not).

- **Partial — DNA-23 relationship is unexplained.** The RFC references DNA-23 in `related[]` (line 25, via RFC-0025) but does not explain how the fix enforces or extends the cosmic naming contract. If the RFC's intent is that cosmic page metadata should respect locale (which it is), that's a DNA-23 concern (cosmic overlay system) and should be in `satisfies[]` with an explanation.

## Axis C — Ecosystem fit

- **FAIL — Proposes editing generated files.** The file system responsibilities table (lines 139–140) lists `src/content/pages/{de,uk}/cosmic/passport.md` and `star-map.md` with role "Fix UK title/description." These files are **generated** by `overlay.pages.generate` (`packages/os/site-kernel-codegen/src/app-boilerplate.ts:52-128`). They carry the `GENERATED` marker and "DO NOT EDIT THIS FILE — Changes are overwritten on the next build" notice. The correct fix is to change the **generator** (`runGenerateOverlayPages`), then regenerate. The RFC must identify `packages/os/site-kernel-codegen/src/app-boilerplate.ts` as the primary file to modify.

- **FAIL — Validation logic in wrong package.** The file system responsibilities table (line 141) proposes `packages/share/src/semantic/` for cosmic i18n validation logic. But build-time validation commands live in `packages/os/site-kernel-checks/`, not in `@gogol/share` (which is for app-agnostic runtime utilities). `packagesImpacted` (line 52) lists only `@gogol/share` — it should list `@gogol/site-kernel-codegen` (generator fix) and, if a validator is still needed, `@gogol/site-kernel-checks`.

- **FAIL — `packagesImpacted` is wrong.** Lists `@gogol/share` but the actual impacted packages are `@gogol/site-kernel-codegen` (generator) and optionally `@gogol/site-kernel-checks` (validator). `@gogol/share` is not impacted by this RFC.

- **Minor — Pipeline placement is stated but unjustified.** The RFC says the validator "runs in `build.check` for all sites with cosmic pages" (line 161). This is the correct pipeline for a blocking check, but the RFC doesn't explain why a validator on **generated** output is needed at all (see Axis F).

## Axis D — Forward-only compliance

No issues. No backward compatibility layers, shims, or dual-paths proposed. The fix replaces the generator's locale-agnostic output with locale-aware output in the same change.

## Axis E — Agent-facing policy

- **Minor — Anti-fabrication gap.** The acceptance criteria include "UK cosmic passport page has localized `title` and `description`" (line 179). The localized Ukrainian text for title/description is content that requires human authoring or explicit agent guidance. The RFC does not provide the Ukrainian strings or specify where they come from (e.g., a new `system.md` field, a labels entry, or a generator-level localization map). An agent implementing this would need to fabricate Ukrainian prose.

- **OK — Status gate.** No self-authorizing language. Implementation notes (lines 190–199) reference correct governance rules (RFC-0224, RFC-0334, RFC-0330).

## Axis F — Pragmatism

- **FAIL — Validator on generated output is unnecessary if the generator is fixed.** The root cause is in `runGenerateOverlayPages`: it uses `brandHeadFromTagline(manifest.identity?.tagline)` for **all locales** (line 81 of `app-boilerplate.ts`), producing identical title/description for DE and UK. If the generator is fixed to produce locale-appropriate metadata, a `cosmic.pages.i18n.validate` command that checks the generated files for German tagline in non-DE locales would always pass — it would be validating deterministic output that the generator controls. The validator adds maintenance burden without catching anything the generator test wouldn't.

- **FAIL — Existing patterns not checked.** The RFC does not check whether an existing command can be extended. `content.references.validate` (in `packages/os/site-kernel-checks/src/content-references.ts`) is mentioned but dismissed without checking if it could be extended with a locale-consistency rule. More importantly, the generator itself (`overlay.pages.generate`) is the right place to enforce locale-appropriate output — a generator test (in `packages/os/site-kernel-codegen`) that asserts non-DE locales don't contain the German tagline would be more effective than a runtime validator on generated files.

## Axis G — Blind spots

- **FAIL — Generator locale-awareness not addressed.** The generator (`runGenerateOverlayPages`) currently has no locale-awareness in title/description generation — it loops over `langs` but uses the same `passportTitle`/`passportDescription` for all locales (lines 82–89, 103–123 of `app-boilerplate.ts`). The RFC must specify how the generator will produce locale-specific metadata. Options include:
  - A localization map in the generator (hardcoded Ukrainian/English cosmic page descriptions), or
  - A new `system.md` field (e.g., `identity.cosmicPageTitles` per locale), or
  - Reading from `site/{lang}/labels.md`. The RFC does not address this design decision.

- **Minor — False positive risk for proper nouns.** The RFC acknowledges (line 175) that "Cosmic Passport" is a proper noun and the check targets the full tagline string. But the tagline "Website, die gefunden wird und Ihrem Betrieb gehört" contains common German words ("Website", "die", "und", "Ihrem") that could appear in legitimate UK descriptions. The RFC should specify exact-match (full tagline string) vs. substring-match behavior.

- **Minor — `brandHeadFromTagline` edge case.** The tagline "Website, die gefunden wird und Ihrem Betrieb gehört" has no em-dash, so `brandHeadFromTagline` returns the entire tagline as the "brand head." The RFC should note that the generator's `brandHeadFromTagline` logic is the mechanism by which the tagline enters the title, and the fix must change how the brand is resolved for non-DE locales.

## Questions for the author

1. **Why does the RFC propose editing generated files instead of fixing the `overlay.pages.generate` generator?** The cosmic page `.md` files are generated outputs with a "DO NOT EDIT" marker. The fix must go into `packages/os/site-kernel-codegen/src/app-boilerplate.ts:runGenerateOverlayPages`. How will the generator produce locale-specific title/description — hardcoded localization map, new `system.md` field, or `labels.md` entries?

2. **Why does `satisfies` list DNA-35 instead of DNA-23?** DNA-35 is "`app.contract.full` as the canonical readiness signal." The cosmic naming contract is DNA-23. The RFC's architectural fit section explicitly calls DNA-35 the "Cosmic naming contract," which is factually wrong. Should this be corrected to DNA-23?

3. **Is `cosmic.pages.i18n.validate` necessary if the generator is fixed?** If `overlay.pages.generate` produces locale-appropriate metadata, a validator checking generated files for German tagline in non-DE locales would always pass. Would a generator-level unit test (asserting non-DE output doesn't contain the tagline) be more effective than a new build-time command?
