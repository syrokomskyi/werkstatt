After

                    B --> D[RegionStrategy]
                    B --> E[CityStrategy]
                    B -.seam.-> F[register new axis]
                    A --> G[unknown → throw]

Problem: resolveProviderEntries is a 70-line if/elif/else with three inline branches — each branch has different entry-construction, dedup, and localization logic, making the function shallow and hard to extend.

Solution: Introduce a ProviderStrategy interface (one per axis); resolveProviderEntries does a registry lookup and delegates; adding a new geo axis means adding a strategy, not editing the dispatcher.

  • locality: each axis strategy in its own module
  • leverage: one dispatch interface, N axes
  • depth: providerEntries interface stays narrow

Problem: countries.ts statically imports only de and uk locale JSON — adding a language requires editing this module and the registeredLocales set, even though GeoServiceConfig.languages already accepts arbitrary language codes.

Solution: Accept a LocaleRegistry in GeoServiceConfig; consumers register the locales they need; getCountry uses the registry instead of module-level state.

  • locality: locale registration in one place
  • leverage: config.languages works for any locale
  • depth: countries module no longer owns locale state
