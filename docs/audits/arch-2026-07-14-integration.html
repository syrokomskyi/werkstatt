Consolidate LeadMessage / Lead / IntegrationEvent into one normalized event shape

Strong in-process

Before

                    A --> C[Lead]

                    classDef leak stroke:#dc2626,stroke-width:2px;

After
                  flowchart TD
                    A[port.ts] --> B[IntegrationEvent]
                    B --> C[kind: lead | message | appointment]
                    B --> D[contact + payload]
                    E[DestinationAdapter] --> B
                    E -.seam.-> F[adapter extracts what it needs]

Problem: Three overlapping shapes (LeadMessage, Lead, IntegrationEvent) represent the same concept with two adapter mapping functions — consumers must learn which shape to use when, and the mappings are pure boilerplate.

Solution: Make IntegrationEvent the single normalized shape; DestinationAdapter implementations extract fields directly; deprecate LeadMessage, Lead, and the mapping functions.

  • locality: one event shape, one place to learn
  • leverage: one interface, no mapping boilerplate
  • depth: port.ts interface shrinks by 2 shapes

Problem: index.ts re-exports 8 modules via export * — consumers import the entire surface even when they only need the port contracts; name collisions across modules are possible.

Solution: Add focused sub-barrels (/port, /delivery, /crm, /runtime); index.ts re-exports only the port contracts; runtime consumers import from the specific sub-barrel.

  • locality: each concern's exports in one barrel
  • leverage: consumers import only what they need
  • depth: index.ts interface shrinks to contracts
