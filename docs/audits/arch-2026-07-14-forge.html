Problem: FORGE_SKILLS is a 375-line hand-maintained array of 29 skill entries — every skill's name, category, concerns, dependsOn, and path are duplicated here and in the SKILL.md frontmatter, while discoverPackSkills already proves runtime discovery from frontmatter works.

Solution: Unify discovery: discoverSkills scans skills/ and parses SKILL.md frontmatter (same logic as discoverPackSkills); FORGE_SKILLS becomes a cached call to discoverSkills(forgeRoot); the hand-maintained array is deleted.

  • locality: skill metadata in one source (frontmatter)
  • leverage: one discovery function, forge + pack skills
  • depth: registry.ts interface shrinks by 260 lines

Problem: index.ts is 139 lines exporting 60+ symbols across 9 concerns — consumers that only need ForgeModule types or config helpers transitively pull in onboarding handlers, migration adapters, and validators.

Solution: Add focused sub-barrels (/types, /config, /onboarding, /os); index.ts re-exports only the most common types; consumers import from the specific sub-barrel.

  • locality: each concern's exports in one barrel
  • leverage: consumers import only what they need
  • depth: index.ts interface shrinks
