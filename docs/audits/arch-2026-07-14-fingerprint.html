Deepen the normalizer dispatcher behind a registry

After
                  flowchart TD
                    A[normalizeFile] --> B[NormalizerRegistry]
                    B --> C[resolve ext → NormalizerEntry]
                    C --> D[normalizer.normalize bytes]
                    D --> E[NormalizeResult]
                    B -.seam.-> F[register new normalizer]

Problem: normalizeFile is a 12-branch if/else chain keyed on file extension — adding a normalizer means editing the dispatcher and the chain grows linearly.

Solution: Replace the chain with a Map<extension, NormalizerEntry> registry; each normalizer module registers itself; the dispatcher does one lookup.

  • locality: each normalizer owns its registration
  • leverage: one lookup interface, N normalizers
  • depth: dispatcher interface shrinks to one map

Problem: shouldIgnore uses naive substring matching (normalized.includes(pattern)) — consumers expect glob patterns but get partial-path false positives.

Solution: Extract a PathMatcher module with proper glob/minimatch semantics; fingerprintTree delegates to it.

  • locality: ignore logic in one module
  • leverage: one matcher, reused across tree ops
