Move EVENT_NAMES and EventPayloadMap to the ontology package

Strong ports & adapters

Problem: The closed event catalog (EVENT_NAMES, EventPayloadMap) is hand-maintained in adapter.ts while the ontology YAML files are the declared source of truth — two places that must stay in sync, validated only by an external command.

Solution: Generate EVENT_NAMES and EventPayloadMap from the ontology YAML catalog; adapter.ts imports the generated types and keeps only the GrowthAdapter interface.

  • locality: event catalog in one source
  • leverage: one schema, type + runtime from it
  • depth: adapter.ts interface shrinks

Problem: emit.ts mixes the pure queue factory, the singleton, the emit() function, and side-effecting window bridge setup at module scope — importing emit.ts in a non-browser environment triggers typeof window checks at load time.

Solution: Move the window.__warpgogol_emit__ bridge setup and teardown into a separate bridge.ts module; emit.ts stays pure and importable anywhere.

  • locality: DOM side-effects in one module
  • leverage: emit.ts importable in Node tests
  • depth: emit.ts interface is pure queue logic
