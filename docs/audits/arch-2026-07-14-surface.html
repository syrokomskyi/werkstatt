Problem: index.ts uses export * from "./governance/index.ts" — a wildcard re-export that makes the barrel's public surface opaque and risks name collisions with the other explicit exports in the same file.

Solution: Replace the wildcard with explicit named exports from the governance barrel, matching the pattern already used for the other modules in index.ts.

  • locality: barrel surface is explicit and auditable
  • leverage: no collision risk with other exports
  • depth: index.ts interface is fully visible

Problem: blueprint.ts is 560 lines mixing 30+ interface/type definitions with helper functions (buildEligibilityMatrix, assembleEntries, generateEntries, resolveSlug) — the type surface and the logic are coupled in one module.

Solution: Extract the Blueprint type definitions into a dedicated blueprint-types.ts module; blueprint.ts imports from it and keeps only the helper functions; consumers that only need types import from blueprint-types.ts.

  • locality: type defs in one module, logic in another
  • leverage: type-only consumers skip logic imports
  • depth: blueprint.ts interface shrinks to functions
