Problem

The readiness interface leaks phase ordering, warning policy, artifact freshness, and missing-evidence interpretation to every caller; nebula.score.compute currently substitutes all-passing inputs when four evidence artifacts are absent.

Solution

Concentrate evidence collection, completeness policy, deterministic checks, rendered checks, qualitative audits, and the final release verdict inside one deep module; incomplete required evidence must be an explicit non-pass state.

  • tests cross one seam

Problem

A single lifecycle action mutates the workpiece, cache clone, monorepo state, Bordbuch, evidence, and mirrors through long implementations with many best-effort catches. Historical fixes repeatedly add one missing commit, push, cleanup, or retry at a time.

Solution

Wins

  • leverage: every Mission transition
  • failure-path tests survive
  • retries become deterministic

Problem

The command registry offers high implementation power but a shallow interface: callers must know hundreds of names, phase distinctions, flags, aliases, generators, and ordering constraints. Sessions repeatedly show wrong flags, wrong manifests, and manual command recovery.

Solution

Place a small goal-oriented capability module at the external seam and keep exact commands as internal adapters selected from declared reads, writes, gates, and prerequisites.

Wins

  • depth: fewer caller facts
  • leverage: one intent, many steps
  • locality: ordering stays internal
  • adapter tests cover routing

Top recommendation

Collapse readiness into one release certification module

This has the highest leverage because it converts every structural, content, accessibility, performance, visual, and qualitative check into one honest release decision. Today the quality interface can report success while core evidence is missing; fixing that seam improves every site produced by Werkstatt before the next release reaches the internet.
