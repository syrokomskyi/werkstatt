# Code Review: fefe41d8...HEAD (RFC-0834 implementation)

### Verdict: Needs revision

The implementation is minimal and correct in its core change (gitignore policy). However, `docs/policies/content-contracts.md:110` still says "GENERATED-marked" which is factually incorrect — the audit established that generators do not emit a GENERATED marker header. The RFC text was corrected but the policy doc was not.

### Axis E — Agent-facing clarity

- **Finding E-1:** `docs/policies/content-contracts.md:110` says "emits `src/image-variants.generated.yaml` (GENERATED-marked, committed for drift detection — see RFC-0834)." The term "GENERATED-marked" is factually incorrect. The audit (Axis A, finding 2) established that `image.variants.generate` writes the manifest via `yamlStringify(manifest)` without a GENERATED header. The RFC text was corrected during enhance to acknowledge this, but the policy doc still uses the old phrasing. An agent reading this policy doc would believe a GENERATED marker is present and may be confused when `grep GENERATED src/image-variants.generated.yaml` returns nothing. Fix: replace "GENERATED-marked" with "generated by `image.variants.generate`" or similar.

### Axis G — Blind spots

No issues beyond E-1. The implementation correctly notes in the RFC that `image.variants.validate` does not implement a stale-manifest rule. The cache clone was updated alongside the workpiece.
