# RFC-0788: Add agent-friendly sitemap extensions for agent crawl discovery

## Context

RFC-0049 implemented `sitemap.generate` — a multi-file sitemap with category split (content/legal), sitemap index, and hreflang alternates. The sitemap XML entries include `<loc>` and `<xhtml:link rel="alternate" hreflang="...">` elements.

RFC-0166 established markdown twins — every full/summary page has a `.md` twin in `public/`. Agents can discover these twins via `agent.json` (`interfaces.twins.pattern`) or via content negotiation (RFC-0785). However, the sitemap does not advertise the markdown alternates.

The [isitagentready.com](https://isitagentready.com/warpgogol.com) audit checks whether the sitemap includes content type alternates — `<xhtml:link rel="alternate" type="text/markdown" href="...">` entries that tell agents "this URL also has a markdown version".

## Problem

The sitemap XML entries only include hreflang alternates — they do not advertise content type alternates (markdown). Agents that crawl the sitemap cannot discover markdown twins without out-of-band knowledge. This reduces agent crawl efficiency: the agent must fetch each URL, check for `.md` twins, or rely on `agent.json` discovery instead of the sitemap.

## Decision

The `sitemap.generate` command is amended to include `<xhtml:link rel="alternate" type="text/markdown" href="...">` entries in sitemap `<url>` blocks for pages that have a corresponding `.md` twin. The `sitemap.validate` command is amended to verify that markdown alternate links are present and correct for all pages with twins.

## Architectural fit

- **DNA-34** (`.well-known/` discovery) — sitemap markdown alternates are another discovery path for agent content.
- **RFC-0049** (sitemap) — this RFC amends the existing `sitemap.generate` and `sitemap.validate` commands, not creating new ones.
- **RFC-0166** (markdown twins) — the sitemap alternates point to the `.md` twins generated by `page.markdown.generate`.
- **RFC-0785** (content negotiation) — sitemap alternates and content negotiation are complementary: sitemap tells agents "markdown exists at this URL", content negotiation lets agents request it via `Accept` header.
- **Site OS operator model** — `scope: app`, `supportsAllSites: true`. The amendment is in the existing sitemap modules.

## Design

### CLI surface

No new commands. `sitemap.generate` and `sitemap.validate` are amended.

### Sitemap XML amendment

Existing `<url>` block:

```xml
<url>
  <loc>https://warpgogol.com/about/</loc>
  <xhtml:link rel="alternate" hreflang="de" href="https://warpgogol.com/about/" />
  <xhtml:link rel="alternate" hreflang="en" href="https://warpgogol.com/en/about/" />
  <xhtml:link rel="alternate" hreflang="x-default" href="https://warpgogol.com/about/" />
</url>
```

Amended `<url>` block (with markdown alternates):

```xml
<url>
  <loc>https://warpgogol.com/about/</loc>
  <xhtml:link rel="alternate" hreflang="de" href="https://warpgogol.com/about/" />
  <xhtml:link rel="alternate" hreflang="en" href="https://warpgogol.com/en/about/" />
  <xhtml:link rel="alternate" hreflang="x-default" href="https://warpgogol.com/about/" />
  <xhtml:link rel="alternate" type="text/markdown" href="https://warpgogol.com/about.md" />
</url>
```

The markdown alternate link is only added when a `.md` twin exists for the page. Pages with `llms.depth: "off"` do not have twins and therefore do not get a markdown alternate link.

### TypeScript contracts

```ts
// packages/werkstatt-site/src/checks/sitemap-helpers.ts — amended

export function generateSitemapXml(

  defaultLanguage: string,

  // For each cluster, if markdownTwins has an entry for cluster.pageId,
  // add <xhtml:link rel="alternate" type="text/markdown" href="..." />
  // after the hreflang alternates.

```

The `markdownTwins` map is built by `runSitemapGenerate` by scanning `public/` for `.md` files and mapping them to page IDs.

### File system responsibilities

| Path | Role |
| --- | --- |
| `packages/werkstatt-site/src/checks/sitemap-helpers.ts` | Amended — `generateSitemapXml` accepts optional `markdownTwins` map |
| `packages/werkstatt-site/src/checks/sitemap.ts` | Amended — `runSitemapGenerate` builds `markdownTwins` map from `public/*.md` |
| `public/sitemap-*.xml` | Output — amended XML with markdown alternate links |

### Output format

No new output format. The sitemap XML is amended in-place with additional `<xhtml:link>` entries.

### Failure modes

- **No markdown twins**: If no `.md` twins exist in `public/`, the sitemap is generated without markdown alternate links. This is not an error — the sitemap is still valid.
- **Stale twins**: If a `.md` twin exists but the page no longer exists (orphaned twin), the sitemap will include a markdown alternate link to a non-existent page. Mitigation: `page.markdown.generate` already prunes stale twins (RFC-0166).
- **Validation mismatch**: `sitemap.validate` reports a violation if a markdown alternate link points to a `.md` file that does not exist in `public/`.

## Rollout

- **Pipeline integration**: `sitemap.generate` already runs in `build.prepare` after `page.markdown.generate`. The amendment is automatic — the generator reads the `.md` files that `page.markdown.generate` just wrote.
- **Existing apps**: All apps get markdown alternate links in their sitemap on the next `build.prepare` run.
- **`agent.enabled: false` apps**: Markdown twins are still generated by `page.markdown.generate` (it is not agent-gated). Sitemap includes markdown alternates regardless of `agent.enabled`.
- **No new files**: The sitemap XML structure is amended in-place, no new sitemap files are created.

## Alternatives considered

1. **Separate `sitemap-agents.xml`** — a dedicated sub-sitemap for agent content. Rejected: markdown alternates are per-page, not per-sitemap. Adding them to existing entries is simpler and follows the sitemap protocol extension pattern.

2. **`<xhtml:link type="application/json">` for structured data** — add JSON-LD alternate links. Rejected: JSON-LD is already embedded in HTML pages via `<script type="application/ld+json">`. Adding it to the sitemap is redundant.

3. **No sitemap changes — agents discover twins via `agent.json`** — Rejected: sitemap is the standard crawl discovery mechanism. Adding markdown alternates makes the sitemap self-describing for agents.

## Risks

- **Sitemap size**: Adding markdown alternate links increases sitemap XML size by ~80 bytes per URL. For a site with 100 pages, this is ~8KB — negligible.
- **Sitemap validation tools**: Some sitemap validators may not recognize `type` attribute on `<xhtml:link>`. This is a standard sitemap extension per the sitemap protocol and should not cause issues.
- **Twin path resolution**: The generator must correctly map page URLs to `.md` twin paths. The mapping is straightforward: `/about/` → `/about.md`, `/de/preise/` → `/de/preise.md`. Same logic as RFC-0785.
