# RFC-0236: Generated-file guard: drift-validate, agent instructions, and source comments for codegen outputs

## Context

During routine content work on `apps/nicaragua-projekt`, an AI agent added LinkedIn links for Denys Kopyl by editing `src/content/prose/de/credits.md` and `src/content/prose/en/credits.md` directly. Those files carry the `GENERATED.` marker in their YAML frontmatter, but the marker alone did not prevent the mistake. On the next `build.prepare`, `material.credits.generate` regenerated both files from the `.credits.yaml` sidecars, silently discarding the edits.

The root cause is a three-way gap:

1. **No drift check.** Nothing in the build or check pipeline detects that a generated file diverges from what its generator would produce from the current source data.
2. **Incomplete agent instructions.** `src/content/AGENTS.md` lists the `material.credits.validate` command and the requirement to add `.credits.yaml` sidecars, but says nothing about `prose/{lang}/credits.md` being generated, or about which source files to edit instead of it.
3. **Opaque template header.** The `prose/credits.md.template` file contains only the generic `{{GENERATED_MARKER}}` token. A reader of the rendered output sees `GENERATED.` but has no pointer to the source domain.

The correct edit for the LinkedIn link was to add `url: https://linkedin.com/in/denyskopyl` to the `parties` entry for Denys Kopyl in each `*.credits.yaml` sidecar under `business/de/assets/`; the generator already handles the `url` field correctly (line 688–690 of `site-kernel-codegen/src/service.ts`).

## Decision

Introduce **three complementary layers** targeting only the confirmed failure mode — generated prose credits pages:

### Layer 1 — `material.credits.drift.validate` command

A new command in `@gogol/site-kernel-checks` that:

1. Reads all `*.credits.yaml` sidecars for the app (reusing `buildMaterialCreditsState`, the same internal helper used by `material.credits.validate`).
2. Re-renders each `prose/{lang}/credits.md` in memory using the same generator logic as `runGenerateMaterialCreditsPage`.
3. Compares the in-memory render against the file on disk (string equality after normalizing line endings).
4. On mismatch: exits non-zero and prints an RFC-0203 Diagnostic for each drifted file:
   ```
   [credits-drift] src/content/prose/de/credits.md — file differs from generator output.
     Do NOT edit this file directly.
     Edit the source: business/de/assets/*.credits.yaml
     Then regenerate: pnpm exec werkstatt run material.credits.generate --app <app>
   ```

The command is registered in `material.credits.validate`'s sibling table and wired into `APPS_CHECK_PIPELINE` after `material.credits.validate` so it runs on every `build.check`. It is also available standalone for manual invocation.

**Scope boundary:** `drift.validate` only covers `prose/{lang}/credits.md` files. Other generated files (middleware, CSS, open-source pages) have their own regeneration paths and are out of scope for this RFC.

### Layer 2 — agent instructions in `AGENTS.template.md` and `src/content/AGENTS.template.md`

`agents.generate` produces two `AGENTS.md` files: the root app guide and `src/content/AGENTS.md`. Both are owned by templates in `packages/os/site-kernel-codegen/src/templates/app-boilerplate/`.

**Change to `src/content/AGENTS.template.md`** — add a new `## Generated prose files` subsection to the "Local reminders" area:

```markdown
- **`prose/{lang}/credits.md` is generated** — do NOT edit it directly. It is regenerated
  from `business/{lang}/assets/*.credits.yaml` sidecars by `material.credits.generate` on
  every `build.prepare`. To change credits content (names, roles, links, license):
  edit the relevant `*.credits.yaml` sidecar, then run
  `pnpm exec werkstatt run material.credits.generate --app {{APP_ID}}` to preview locally.
  Run `material.credits.drift.validate` to confirm no uncommitted manual edits remain.
```

**Change to root `AGENTS.template.md`** — extend the `## Generated files (do not edit manually)` table to include the credits row:

```markdown
| `src/content/prose/*/credits.md` | `material.credits.generate` | After editing any `*.credits.yaml` sidecar |
```

Both changes propagate to all apps on the next `agents.generate` run.

### Layer 3 — explicit source comment in `prose/credits.md.template`

Add a HTML comment block directly after the frontmatter closer (`---`) in `packages/os/site-kernel-codegen/src/templates/service/src/content/prose/credits.md.template`:

```
<!--
  GENERATED FILE — do not edit directly.
  Source: business/{lang}/assets/*.credits.yaml
  Regenerate: pnpm exec werkstatt run material.credits.generate --app <app-id>
  Drift check: pnpm exec werkstatt run material.credits.drift.validate --app <app-id>
-->
```

The comment is rendered into every `prose/{lang}/credits.md` and is immediately visible to any agent that reads the file before attempting an edit.

## Why three layers

Each layer catches a different failure mode independently:

| Layer                   | Catches                           | When                         |
| ----------------------- | --------------------------------- | ---------------------------- |
| `drift.validate`        | Edits already made and committed  | CI / `build.check`           |
| `AGENTS.md` instruction | Edits planned but not yet started | Agent planning phase         |
| Template comment        | Edits started on the file         | Agent mid-edit, on file read |

All three are cheap and non-destructive. Together they create a closed loop: the comment redirects at read time → the instruction redirects at planning time → the validate command catches anything that slips through.

## Alternatives considered

- **Fail `build.prepare` if the credits file is edited.** Rejected: `build.prepare` runs `material.credits.generate`, which overwrites the file unconditionally. It is already self-healing. A gate there would block valid workflows where the developer edits the file as a scratchpad before fixing the YAML.
- **Checksum or `.gitattributes` lock on the generated file.** Rejected: heavy tooling with poor agent readability. A prose check command plus a human-readable error message is more actionable.
- **Single-layer fix (AGENTS.md only).** Insufficient: agents operate under constrained context windows and may not have loaded `AGENTS.md` when starting an edit. The in-file comment (Layer 3) and the CI gate (Layer 1) provide defence-in-depth without relying on prior context loading.

## Implementation notes for agents

- **`drift.validate` handler:** `packages/os/site-kernel-checks/src/material-credits.ts` — add `runMaterialCreditsDriftValidate` function. Import `renderMaterialCreditsPage` (or inline the render logic extracted from `runGenerateMaterialCreditsPage` in `site-kernel-codegen/src/service.ts`). The render logic must be extracted into a shared helper importable by both codegen and checks without creating a circular dependency — preferred location: a new `packages/os/site-kernel-codegen/src/credits-render.ts` that both `service.ts` and the check import.
- **Command registration:** add `material.credits.drift.validate` to the existing command table that registers `material.credits.validate` and `material.credits.generate`; mark `scope: "app"`, `mutatesState: false`.
- **Pipeline insertion:** `packages/os/site-kernel/src/pipelines/apps-check.ts` (or the equivalent pipeline table for `APPS_CHECK_PIPELINE`) — insert `{ command: "material.credits.drift.validate" }` after `{ command: "material.credits.validate" }`.
- **Template edits:** make the three template file changes described in Layers 2 and 3 above; regenerate affected apps with `agents.generate` to sync `AGENTS.md` outputs.
- **Tests:** add a unit test in `packages/os/site-kernel-checks/src/__tests__/` that (a) creates a minimal in-memory `credits.yaml`, runs the renderer, mutates the on-disk output, and verifies `drift.validate` exits non-zero with the expected diagnostic message; (b) verifies a clean state exits zero.
