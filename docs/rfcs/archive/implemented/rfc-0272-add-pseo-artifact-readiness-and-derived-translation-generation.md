# RFC-0272: Add PSEO artifact readiness and derived translation generation

## Context

RFC-0197 introduced frozen, approved LLM enrichment. RFC-0215 introduced derived-content source hashing for translations and generated copy. RFC-0271 adds a module authoring language, so PSEO can generate canonical artifacts in the language the operator understands best, even when that language differs from the site's default language.

The missing lifecycle is the bridge between those contracts: after a generated artifact has been reviewed and fixed in the module authoring language, the operator needs a durable way to say "this source is ready for translation." The next generation pass should then create or refresh translations for the module's target languages.

## Problem

Today an enriched artifact has `approved: true|false`, but approval alone is ambiguous:

- approved for rendering in the authoring language;
- approved as a canonical translation source;
- approved after a later source edit;
- approved as a machine translation.

The system needs separate states for human approval and translation readiness. It also needs a deterministic link between a translated artifact and the exact source artifact it was translated from.

## Decision

PSEO generated artifacts gain a **review lifecycle**:

1. `draft`: generated by `surface.enrich`, never rendered.
2. `approved`: reviewed and allowed to render in the artifact's own language.
3. `readyForTranslation`: approved source artifact is declared stable enough for derived translations.
4. `translationDraft`: machine-generated derived artifact in a target language, never rendered as indexable content.
5. `translationApproved`: translated artifact reviewed in the target language and allowed to render.
6. `outdated`: a derived artifact whose stored `sourceHash` no longer matches the current ready source.

`readyForTranslation` is explicit. It is not implied by `approved`.

Translation generation is automatic over the ready queue, but it is not part of normal deterministic build. A dedicated command, `surface.translation.generate`, processes every ready source artifact for every target language declared by the module context. A local wrapper may call this command before a build, but CI `build.check` and Astro SSG must never call an LLM.

Approval is not transitive through translation. A perfect review of the master-locale artifact proves only that source artifact; every published locale needs its own target-language quality gate. This gate may combine deterministic checks, glossary validation, full human review for the first N artifacts per template/field, sampling after stabilization, and always-human review for claims fields.

## Architectural fit

- RFC-0197 already defines generate-once, freeze, review, and render only approved content; this RFC adds the missing translation-readiness state.
- RFC-0215 already defines `derivedFrom` and `sourceHash`; translated PSEO artifacts reuse that lineage instead of inventing a second staleness model.
- RFC-0271 supplies the module authoring language and target languages that drive this lifecycle.
- RFC-0273 supplies the translator note required before target-language generation can run.
- RFC-0274 consumes target-language approval state before deciding whether a translated URL may be indexable.

## Design

### Artifact metadata

The existing enriched content entry keeps its frozen prose, but gains lifecycle metadata:

```yaml
pageId: website-local:friseur:deu:bw:karlsruhe:balayage
field: narrative
lang: uk
module: pseo
authoringLanguage: uk
provenance:
  promptId: website-local-narrative-v2
  model: gpt-5
  generatedAt: 2026-07-03T10:00:00.000Z
  approved: true
lifecycle:
  status: readyForTranslation
  reviewedAt: 2026-07-03T11:00:00.000Z
  reviewedBy: human:operator
  readyForTranslationAt: 2026-07-03T11:05:00.000Z
  contentHash: sha256:source-current
```

A derived translation stores RFC-0215 lineage:

```yaml
pageId: website-local:friseur:deu:bw:karlsruhe:balayage
field: narrative
lang: de
module: pseo
provenance:
  promptId: pseo-translation-de-v1
  model: gpt-5
  generatedAt: 2026-07-03T11:10:00.000Z
  approved: false
lifecycle:
  status: translationDraft
derived:
  derivedFrom: enriched:pseo/website-local/uk/website-local:friseur:deu:bw:karlsruhe:balayage#narrative
  sourceHash: sha256:source-current
  translatorNoteId: pseo/de
  glossaryId: pseo/de
quality:
  targetGate: pending
  echoChecks: pending
  glossaryChecks: pending
  humanReview: pending
```

### CLI surface

```sh
# Mark a reviewed source artifact as ready for translation.
pnpm exec site-kernel run surface.artifact.ready --app warpgogol-com \
  --module pseo \
  --page-id website-local:friseur:deu:bw:karlsruhe:balayage \
  --field narrative

# Generate all missing or outdated target-language drafts from ready source artifacts.
pnpm exec site-kernel run surface.translation.generate --app warpgogol-com --module pseo --json

# Validate lifecycle, source hashes, approval gates, and stale translations.
pnpm exec site-kernel run surface.translation.validate --app warpgogol-com --module pseo --json

# Validate deterministic target-language quality gates.
pnpm exec site-kernel run surface.translation.qa.validate --app warpgogol-com --module pseo --json
```

### Generation rules

1. `surface.enrich` generates only authoring-language source artifacts by default.
2. `surface.artifact.ready` refuses to mark an artifact ready unless it is approved and has a stable content hash.
3. `surface.translation.generate` reads module context, approved translator notes, glossary data, ready source artifacts, target languages, and the structured records that fed the source artifact.
4. Existing target artifacts are skipped when their `sourceHash` matches the current source hash.
5. Existing target artifacts are regenerated only with `--regenerate-outdated` or when they are still unapproved drafts.
6. Target artifacts are always written `approved: false`.
7. Translation prompts receive master prose plus structured record data, glossary terms, and the target-language translator note. They must not translate prose-to-prose blindly.
8. `surface.generate` excludes unapproved or target-gate-failing translations from indexable rendering. It may render a noindex fallback only when the module policy explicitly allows it.

### Validation rules

| Rule | Severity | Meaning |
| --- | --- | --- |
| `PSEO-ART-01` | error | Ready artifact is not approved |
| `PSEO-ART-02` | error | Target translation has no `derivedFrom` or `sourceHash` |
| `PSEO-ART-03` | warning by default | Target translation is outdated |
| `PSEO-ART-04` | error | Indexable page would render from unapproved translation |
| `PSEO-ART-05` | error | Translation generated without an approved translator note |
| `PSEO-ART-06` | error | Translation generated without a glossary where module context requires one |
| `PSEO-ART-07` | error | Claims field translated without required human target-language review |
| `PSEO-ART-08` | warning/error by policy | Target-locale sample review quota is not met |

Deterministic QA checks include echo checks for numbers, entities, URLs, placeholders, page ids, and record-bound claims. Target-language lint checks glossary terms, forbidden terms, register requirements such as German `Sie` form, and terms that must not be translated.

## Failure modes

- Ready source changed after translation: translated artifact becomes `outdated` and cannot be treated as current.
- Missing translator note for target language: generation fails before calling a model.
- Missing glossary for a target language whose policy requires it: generation fails before calling a model.
- Provider unavailable: generation exits non-zero with no partial approval; existing frozen content remains buildable.
- Translation draft exists but is unapproved or target-gate-failing: it is review work, not public content.

## Rollout

1. Extend enriched artifact metadata with lifecycle and hash fields.
2. Add `surface.artifact.ready` and `surface.translation.validate`.
3. Add `surface.translation.generate` over the ready queue.
4. Add `surface.translation.qa.validate` with echo, glossary, and review-policy checks.
5. Migrate existing approved authoring-language entries by stamping `contentHash`, but do not mark them ready automatically.
6. Teach `surface.generate` to reject indexable rendering from unapproved or target-gate-failing translated artifacts.

## Alternatives considered

- **Use `approved: true` as ready-for-translation.** Rejected: rendering approval and source-stability approval are different human decisions.
- **Translate during normal build.** Rejected: this breaks RFC-0197 determinism, makes CI cost unpredictable, and can ship provider failures as build failures.
- **Auto-approve translations.** Rejected: target-language quality still needs review, especially for local SEO pages and legally sensitive claims.
- **Translate prose-to-prose only.** Rejected: the translator must see the structured record and glossary so output can be validated against source facts in every language.

## Risks

- The ready queue can accumulate stale drafts. Mitigation: `surface.translation.validate` reports outdated and pending artifacts with source hashes.
- Operators may expect normal build to translate content. Mitigation: command names and diagnostics must say that LLM translation is a generation pass, not SSG.
- Source artifacts can be edited after translations are approved. Mitigation: sourceHash comparison marks translations outdated.
- Target-language review can become a bottleneck. Mitigation: deterministic QA plus first-N full review and sampling after stabilization; claims remain always-human.

## Implementation notes for agents

- Never stamp an artifact ready for translation merely to clear a warning. The source must actually be reviewed and stable.
- Never overwrite an approved translation without an explicit regenerate flag and a review trail.
- Never treat master-locale approval as approval of a translated locale.
- Keep the normal build deterministic. The automatic part is queue processing by `surface.translation.generate`, not hidden model calls in SSG.
