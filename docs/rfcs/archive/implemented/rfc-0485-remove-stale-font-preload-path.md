# RFC-0485: Remove stale font preload for /fonts/inter-400.woff2

## Context

RFC-0164 established self-hosted fonts and was superseded by RFC-0371, which replaced the copy-to-`public/fonts/` pipeline with Fontsource CSS `@import` statements. The `fonts.imports.generate` command (RFC-0371, `packages/os/site-kernel-codegen/src/fonts-imports.ts`) generates `fonts.imports.css` with `@import "@fontsource/inter/400.css"` (and other weights/families). Vite bundles these CSS imports, and the `@font-face` declarations inside them reference hashed `_astro/` font assets (e.g. `/_astro/inter-latin-400-normal.abc123.woff2`).

The layout component (`packages/ui/src/components/layout/layout-component.astro:183`) hardcodes a preload link:

```html
<link rel="preload" as="font" type="font/woff2" href="/fonts/inter-400.woff2" crossorigin />
```

This path (`/fonts/inter-400.woff2`) does not exist — there is no `public/fonts/` directory, and Vite does not emit font files to that path. The font files are bundled as hashed `_astro/` assets via the `@fontsource` CSS imports.

## Problem

Every page load produces a 404 for `/fonts/inter-400.woff2` in the browser network tab. The preload is dead — it points to a file that does not exist and was never generated by any codegen command.

The `@fontsource` CSS `@font-face` declarations already handle font loading correctly, including the correct hashed URLs. The preload link adds nothing except a 404.

## Decision

Remove the hardcoded `<link rel="preload">` tag from `layout-component.astro`. The `@fontsource` `@font-face` declarations in `fonts.imports.css` (imported via `global.css`) are the canonical font loading mechanism. Vite handles the bundling and URL hashing.

## Design

In `packages/ui/src/components/layout/layout-component.astro`, remove:

```astro
<link rel="preload" as="font" type="font/woff2" href="/fonts/inter-400.woff2" crossorigin />
```

And its accompanying comment block:

```astro
{
  /* RFC-0164: self-hosted fonts. @font-face is inlined via global.css → fonts.generated.css
    (no third-party origin, no GDPR exposure). Preload the body base weight for early paint. */
}
```

## Architectural fit

- **RFC-0371 (Fontsource CSS imports, current authority):** RFC-0371 superseded RFC-0164 and switched font delivery from copied `public/fonts/*.woff2` files to Fontsource CSS `@import` statements with Vite-bundled `/_astro/*.woff2` assets. The preload link was not updated during this migration and became stale. This RFC amends RFC-0371 by removing the dead preload.
- **RFC-0164 (Self-hosted fonts, superseded):** The preload was originally added by RFC-0164, which referenced `/fonts/inter-400.woff2` as the woff2 path. RFC-0371 removed that path. Referenced for historical context only.

## Alternatives considered

- **Dynamic preload path from generated CSS.** Read the hashed font URL from the generated CSS and inject it as the preload href. Rejected: adds complexity (CSS parsing at build time) for minimal benefit. The `@font-face` declaration in the CSS already provides the browser with the font URL — the preload hint only saves the CSS parse step, which is negligible for self-hosted fonts inlined in `global.css`.

- **Copy font files to public/fonts/.** Copy the `@fontsource` woff2 files to `public/fonts/` so the preload path resolves. Rejected: duplicates font files and breaks the Vite bundling model. The `@fontsource` CSS imports are the single source of truth for font assets.

- **Keep preload, fix path.** Change the href to the Vite-hashed URL. Rejected: the hash changes on every build, making a hardcoded path impossible. A dynamic approach would require build-time CSS parsing, which is the same as the "dynamic preload" alternative above.

## Rollout

- Atomic removal in a single commit — the `<link rel="preload">` tag and its comment block are deleted from `layout-component.astro`.
- No migration window needed — all apps inherit the fix via `@gogol/ui` shared layout.
- No app code changes required — `appsImpacted` is empty.
- The `CHANGE_SUMMARY` block in `layout-component.astro` must be updated with a new entry referencing this RFC (DNA-42 Compass markup contract).

## Risks

- **Slight font paint delay.** Without the preload hint, the browser discovers the font URL when it parses the `@font-face` declaration in `global.css` instead of from the preload scanner. For self-hosted fonts inlined in the CSS, this delay is negligible (same origin, no DNS lookup, no redirect). The `font-display: swap` in `@fontsource` CSS ensures text is visible during font load.
