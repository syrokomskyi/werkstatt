# RFC-0273: Generate approved translator notes per PSEO module language

## Context

PSEO translations are not generic string localization. A Bedarfskarte or local hub contains product language, search intent, geo terms, facts, disclaimers, internal-link labels, and tone. A high-quality translation must preserve the source's factual load while sounding native in the target language.

The operator wants translator notes to be generated through the same AI-assisted ecosystem. That is reasonable, but the notes themselves become a load-bearing prompt artifact and must be frozen, reviewed, approved, and invalidated when module context changes. Terminology must be even stricter: it is data, not prose. A glossary term can be linted; a paragraph of advice cannot.

## Problem

Without per-language translator notes:

- translation quality depends on a hidden prompt in code;
- modules with different voice and risk boundaries share one generic instruction;
- target languages can lose brand terms or accidentally invent local claims;
- changing module context does not invalidate old translation instructions.

## Decision

Each PSEO module and target language has a **translator note**: a frozen, non-public, approval-gated instruction artifact used by `surface.translation.generate`. Translator notes are generated by `surface.translation.notes.generate` from the module context, supported languages, source/target language pair, existing approved examples, and optional glossary entries.

A translator note must be approved before it can be used for generated translations. Notes carry provenance and a `moduleContextHash`; when the module context changes, the note becomes stale. Each module target language may also declare a machine-readable glossary. When a glossary exists or is required by module context, translation generation and QA pin the glossary id in provenance and validate terms deterministically.

## Architectural fit

- RFC-0197's frozen-provenance model applies to prompt-support artifacts as well as rendered page prose.
- RFC-0215's sourceHash discipline applies through `moduleContextHash`, so translation instructions are invalidated when their source context changes.
- RFC-0271 defines the module context that notes are generated from.
- RFC-0272 consumes approved notes during translation generation.
- Glossary data feeds RFC-0272 echo and target-language QA checks.

## Design

### File system responsibilities

Translator notes live under the enriched content tree because they are generated, reviewed artifacts, but they are not renderable pages:

| Path | Role |
| --- | --- |
| `apps/*/src/content/enriched/_translation-notes/<module>/<targetLang>.md` | Frozen translator note for one module and target language |
| `apps/*/src/content/enriched/_translation-glossaries/<module>/<targetLang>.yaml` | Machine-readable term policy for one module and target language |
| `apps/*/src/content/enriched/_translation-notes/<module>/<targetLang>.claims.yaml` | Optional claim/provenance sidecar if implementation chooses sidecars |

The implementation may store metadata in frontmatter or sidecars, but it must expose the same logical fields to validators.

### Translator note metadata

```yaml
module: pseo
sourceLanguage: uk
targetLanguage: de
noteId: pseo/de
moduleContextHash: sha256:context-current
provenance:
  promptId: translator-note-v1
  model: gpt-5
  generatedAt: 2026-07-03T12:00:00.000Z
  approved: false
lifecycle:
  status: draft
```

### Required note sections

A valid translator note contains these machine-readable or heading-addressable sections:

- `Purpose`: what this module's translated artifacts are for.
- `Audience`: who reads the target-language copy.
- `Voice`: tone, register, and sentence rhythm in the target language.
- `Do not translate`: brand names, product names, route identity tokens, claim subjects, and code-like terms.
- `Must preserve exactly`: numbers, dates, prices, legal references, source claims, URLs, pageIds, and geo identifiers.
- `Transcreate`: expressions that should sound natural instead of literal.
- `Forbidden moves`: invented facts, invented reviews, invented regional statistics, keyword stuffing, synonym spinning.
- `Examples`: at least two approved source-to-target examples once available.

### Glossary data

```yaml
id: pseo/de
module: pseo
targetLanguage: de
terms:
  - concept: digital-foundation
    source:
      uk: "цифровий фундамент"
    target: "Digitales Fundament"
    rule: exact
    caseSensitive: true
  - concept: formal-you
    rule: require-register
    target: "Sie"
forbidden:
  - term: "billig"
    reason: "Avoids discount positioning in the PSEO module."
```

The glossary is allowed to be AI-drafted, but it follows the same freeze-review-approve lifecycle. A translation cannot be generated from an unapproved required glossary.

### CLI surface

```sh
pnpm exec site-kernel run surface.translation.notes.generate --app warpgogol-com --module pseo --target de
pnpm exec site-kernel run surface.translation.notes.review --app warpgogol-com --module pseo --target de
pnpm exec site-kernel run surface.translation.notes.review --app warpgogol-com --module pseo --target de --approve
pnpm exec site-kernel run surface.translation.notes.validate --app warpgogol-com --module pseo --json
pnpm exec site-kernel run surface.translation.glossary.validate --app warpgogol-com --module pseo --json
```

### Validation rules

| Rule | Severity | Meaning |
| --- | --- | --- |
| `PSEO-NOTE-01` | error | Missing translator note for a module target language |
| `PSEO-NOTE-02` | error | Translator note is not approved but translation generation is requested |
| `PSEO-NOTE-03` | warning | Translator note is stale against current module context |
| `PSEO-NOTE-04` | error | Required section missing |
| `PSEO-NOTE-05` | warning | No approved examples yet |
| `PSEO-GLOSS-01` | error | Required glossary missing or unapproved |
| `PSEO-GLOSS-02` | error | Glossary entry is malformed or ambiguous |
| `PSEO-GLOSS-03` | warning | Glossary has no examples for a required term |

## Failure modes

- Missing note or required glossary: `surface.translation.generate` exits before provider calls.
- Stale note: validation warns; generation may require `--allow-stale-note` only for draft regeneration, never for approving public translations.
- Note generated in the wrong source language: error, because it may not reflect the authoring artifact language.
- Note has no forbidden-claims section: error, because it is a safety boundary.

## Rollout

1. Add note schema and validation.
2. Add glossary schema and validation.
3. Generate a `pseo/de` translator note and glossary for `warpgogol-com` from the Ukrainian master context.
4. Review and approve the note and glossary manually.
5. Make `surface.translation.generate` refuse target-language generation without approved required note/glossary artifacts.
6. Add approved examples back into the note after the first few translations are reviewed.

## Alternatives considered

- **One global translator note.** Rejected: modules differ in claims, tone, audience, and legal/product risk.
- **Hard-code translator prompt in TypeScript.** Rejected: the translator's instructions need review, provenance, and version control.
- **Let the translation model infer style from source only.** Rejected: local SEO pages need explicit fact preservation and anti-keyword-stuffing rules.
- **Put terminology only in note prose.** Rejected: terms must be machine-readable so validators can catch drift and mistranslation.

## Risks

- A poor note can degrade every translation in a module. Mitigation: notes require approval and examples before broad use.
- Notes can become stale after module positioning changes. Mitigation: `moduleContextHash` invalidates them.
- Notes can become too verbose for reliable model use. Mitigation: required sections should be concise and validators should flag oversized notes if needed.
- Glossaries can become incomplete and create false confidence. Mitigation: QA reports unknown repeated terms and lets reviewers promote them into glossary entries.

## Implementation notes for agents

- Translator notes are not marketing copy. They are operator instructions and should be concise, explicit, and testable.
- Never generate translations from an unapproved translator note or required glossary.
- When module context changes materially, refresh the note before approving new translations.
