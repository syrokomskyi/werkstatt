## 3. Step sequence

### Step 1. Add `createDevNormalizeMiddleware()` to `@warpgogol/share/text-normalize.ts`

**Goal:** Implement the dev middleware factory function that wraps `normalizeHtml()` with try/catch and returns an Astro `MiddlewareHandler`.

**Agent actions:**

- Add `import type { MiddlewareHandler } from "astro"` at the top of `packages/share/src/text-normalize.ts` (with the other imports).
- Add `createDevNormalizeMiddleware(config: NormalizeConfig): MiddlewareHandler` function at the end of the file.
- The function returns an async middleware that: checks `config.enabled`, checks `content-type` includes `text/html`, wraps `normalizeHtml(body, config)` in try/catch, returns normalized response or falls back to original on error.
- Do NOT add the export to the root barrel (`src/index.ts`) — `@warpgogol/share/text-normalize` is already a subpath entry point in `package.json` exports.

**Validation:**

- `pnpm --filter @warpgogol/share run build:check` — TypeScript compiles.
- `grep -n "createDevNormalizeMiddleware" packages/share/src/text-normalize.ts` — export exists.

**Completion criterion:** `createDevNormalizeMiddleware` is exported from `packages/share/src/text-normalize.ts` and `build:check` passes.

**Human review:** no

### Step 2. Add unit tests for `createDevNormalizeMiddleware()`

**Goal:** Test the middleware factory: enabled config normalizes, disabled config is pass-through, non-HTML responses are pass-through, try/catch falls back on error.

**Agent actions:**

- Add test cases to `packages/share/src/tests/text-normalize.test.ts`:
  - `createDevNormalizeMiddleware` with enabled config normalizes em-dashes to hyphens in HTML response.
  - `createDevNormalizeMiddleware` with `config.enabled = false` is a pass-through (returns original response).
  - `createDevNormalizeMiddleware` with non-HTML content-type is a pass-through.
  - `createDevNormalizeMiddleware` falls back to original response when `normalizeHtml()` throws.
- Tests use `vi.mock` or direct instantiation of `NormalizeConfig` with all signals enabled.
- Mock `next` to return a `new Response(htmlBody, { headers: { "content-type": "text/html" } })`.

**Validation:**

- `pnpm --filter @warpgogol/share test` — all tests pass.

**Completion criterion:** All new test cases pass and cover the four scenarios (enabled, disabled, non-HTML, error fallback).

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --------------- | ---------------------- |
| Dev middleware performance (~1-5ms + ~1ms config load) | Step 1 uses try/catch and per-request config loading; Step 6 verifies dev parity without measuring performance (dev render times are 100-500ms, overhead is noise) |
| Dev/prod drift | Step 1 reuses `normalizeHtml()` from the same module; Step 6 verifies both dev and dist output match |
| `smartypants: false` changes dev rendering | Step 4 gates it by `isAstroDev` (dev-only); Step 6 confirms production keeps default behavior |
| Agent misinterpretation (thinking middleware normalizes sources) | Step 7 updates AGENTS.md to clarify the middleware transforms HTML responses only |
| Template regeneration churn | Step 5 regenerates via existing commands; both files are GENERATED with marker |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-N, run `pnpm exec site-kernel run rfc.supersede.propose --id RFC-0569 --reason "..." --invariant "DNA-N"` instead of working around it.
- If `loadSystemManifest()` cannot be imported in the dev middleware context (e.g. Vite SSR externalization issue), escalate to the operator — do not switch to a different config-loading mechanism without discussion.
