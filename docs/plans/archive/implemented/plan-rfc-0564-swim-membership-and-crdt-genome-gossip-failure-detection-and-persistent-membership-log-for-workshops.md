### Step 2. Implement CRDT genome log

**Goal:** Implement the G-Set genome log with NDJSON append, set-union merge, Ed25519 signature verification, and restart recovery.

**Agent actions:**

- Create `packages/os/site-kernel/src/swim/genome-log.ts` with:
  - `appendGenomeEntry(entry: GenomeLogEntry)` — appends NDJSON line to `werkstatt.genome.log`.
  - `readGenomeLog(): GenomeLogEntry[]` — reads all entries, verifies each signature, skips invalid entries with warning, returns valid entries.
  - `mergeGenomeLogs(local: GenomeLogEntry[], peer: GenomeLogEntry[]): GenomeLogEntry[]` — G-Set union by `(workshopId, event, timestamp, source)` identity.
  - `deriveMembershipView(entries: GenomeLogEntry[]): SwimMembershipView` — replays entries in timestamp order, latest entry per workshopId determines status.
  - `signGenomeEntry(entry, privateKey)` — signs entry using Ed25519 via `@warpgogol/passport` `signBytes`.
  - `verifyGenomeEntry(entry, publicKey)` — verifies signature via `@warpgogol/passport` `verifyBytes`.
  - `getGenomeLogSize()` — returns file size in bytes (for 10MB threshold warning).
- Add `@warpgogol/passport` to `packages/os/site-kernel` dependencies (direct dependency — not via `site-kernel-integrity`).
- Import `signBytes`/`verifyBytes` from `@warpgogol/passport`.
- Read `PASSPORT_SIGNING_KEY` env var for private key.
- Read `werkstatt.identity.json` for public key and operatorVC (RFC-0558, already implemented).
- Add Compass scaffolding per DNA-42.

**Validation:**

- `pnpm --filter @warpgogol/site-kernel run build:check` — typecheck passes.

**Completion criterion:** `genome-log.ts` exists with all functions, build:check passes.

**Human review:** no

### Step 3. Implement SWIM command handlers using `swim` npm package

**Goal:** Implement the four command handlers (`swim.join`, `swim.leave`, `swim.members`, `swim.status`) using the `swim` npm package for the SWIM protocol.

**Agent actions:**

- Add `swim` npm package to `packages/os/site-kernel/package.json` dependencies.
- Create `packages/os/site-kernel/src/swim/handlers.ts` with four handler functions:
  - `runSwimJoin` — reads `--seed` flag, creates `werkstatt.swim.json` if missing (via `createSwimConfig`, generating UUID v7 for workshopId), reads `werkstatt.identity.json` for operatorVC and PASSPORT_SIGNING_KEY for signing. If identity not bootstrapped, exits with `identity-not-bootstrapped`. Instantiates `Swim` from the `swim` package with config, calls `bootstrap([seed])`, appends `alive` entry to genome log (signed with Ed25519), returns membership view. On seed unreachable, exits with code 1 and `seed-unreachable` error. **Ephemeral:** SWIM instance is destroyed when command exits — no long-running daemon.
  - `runSwimLeave` — broadcasts `left` event to genome log, calls `swim.leave()` on the `swim` instance, returns success. On config missing, exits with code 1 and `config-not-found`.
  - `runSwimMembers` — loads config, reads genome log, derives membership view, returns `SwimMembershipView` as JSON. On config missing, exits with code 1.
  - `runSwimStatus` — loads config, reads genome log, reports local status (alive, peers count, genome log size, warnings if >10MB or peers=0). Exit 0 with warnings.
- Each handler returns `KernelCommandResult` with `data`, `status`, `summary` per the RFC output format.
- Add Compass scaffolding per DNA-42.

**Validation:**

- `pnpm --filter @warpgogol/site-kernel run build:check` — typecheck passes.

**Completion criterion:** `handlers.ts` exists with all four handlers, build:check passes.

**Human review:** no

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| False positives (workshop marked dead but alive) | Step 3: `swim` npm package implements Lifeguard extensions with configurable suspicion timeout |
| Genome log growth | Step 2: `getGenomeLogSize()` + Step 3: `swim.status` warns at 10MB threshold |
| Agent misinterpretation (manual genome log edits) | Step 2: signature verification on restart skips invalid entries; RFC implementation notes already state the constraint |
| Gossip overhead | Step 3: `swim` package config has defaults; probe interval is configurable in `werkstatt.swim.json` |
| `swim` npm package maintenance risk | Step 3: package is MIT-licensed, 239 weekly downloads, stable API. If unmaintained, can be forked or replaced — the module boundary isolates the dependency |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-1, run `pnpm exec site-kernel run rfc.supersede.propose --id RFC-0564 --reason "..." --invariant "DNA-1"` instead of working around it.
- If the `swim` npm package is incompatible with the TypeScript strict mode or ESM module system, evaluate `@libp2p/swim` or `swim-hashring` as alternatives before falling back to a stub implementation.
- If the Ed25519 key reuse from RFC-0558's `PASSPORT_SIGNING_KEY` creates a circular dependency between `packages/os/site-kernel` and `packages/passport`, extract the signing primitives into a shared utility or use dynamic import to break the cycle.
