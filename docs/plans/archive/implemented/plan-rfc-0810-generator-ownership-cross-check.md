## 3. Step sequence

### Step 1. Make `module` required in `OwnershipEntry` and implement `ownership.generator.cross-check` command

**Goal:** Update the `OwnershipEntry` interface to make `module` a required field, then create the command handler that cross-references registered `.generate` commands against `GENERATOR_OWNERSHIP_MAP`.

**Agent actions:**

- Edit `packages/werkstatt-site/src/checks/generator-ownership.ts`:
  - Change `module?: string` to `module: string` in the `OwnershipEntry` interface (line 52)
  - Update CHANGE_SUMMARY with RFC-0810 entry
- Create `packages/werkstatt-site/src/checks/ownership-cross-check.ts`
- Import `listRegisteredKernelCommands` from `@warpgogol/werkstatt/kernel`
- Import `fileExists` from `@warpgogol/werkstatt-site/share/fs`
- Import `GENERATOR_OWNERSHIP_MAP` from `./generator-ownership.ts`
- Import `diagnosticsResult` from `./result-helpers.ts`
- Implement `runOwnershipGeneratorCrossCheck`:
  1. Call `listRegisteredKernelCommands(context.workspaceRoot)` to get all registered commands
  2. Filter to commands with `name` ending in `.generate` AND `scope: "app"`
  3. Build a `Set<string>` of command names from `GENERATOR_OWNERSHIP_MAP` entries
  4. For each app-scoped `.generate` command, check if it has at least one entry in the map → `OWN-XCHECK-01` if not
  5. For each ownership map entry, check if its `command` field matches a registered command → `OWN-XCHECK-02` if not
  6. For each ownership map entry, check if `module` field is present and non-empty → `OWN-XCHECK-03` (error) if missing. Then call `await fileExists(join(context.workspaceRoot, entry.module))` → `OWN-XCHECK-03` (warning) if returns false
  7. Return `diagnosticsResult("ownership.generator.cross-check", diagnostics)`
- Add MODULE_CONTRACT and CHANGE_SUMMARY Compass scaffolding

**Validation:**

- `pnpm --filter @warpgogol/werkstatt-site run build:check` — TypeScript compiles

**Completion criterion:** File exists, TypeScript compiles, handler function exported.

**Human review:** no

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| False positives for conditional generators | Step 1: check only verifies entry existence, not file presence; `conditional: true` entries are valid |
| False positives for workspace-scoped generators | Step 1: filter by `scope: "app"` only; Step 4: test case verifies workspace-scoped commands are skipped |
| Post-build and ephemeral outputs | Step 1: `scope: "app"` filter excludes `dist.sitemap.images.generate` and `print.pdf.generate` |
| Maintenance burden | Minimal — registry cross-reference with no file I/O beyond `module` path existence check |

## 6. Escalation triggers

- If implementation reveals that `listRegisteredKernelCommands` does not return `scope` for all commands, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0810 --reason "command registry does not expose scope field" --invariant "DNA-58"` instead of working around it.
