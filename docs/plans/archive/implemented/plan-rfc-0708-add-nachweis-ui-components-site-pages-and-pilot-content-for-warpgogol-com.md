## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Dynamic route complexity | Step 3 creates `getNachweisRoutes()` following the established `getParticipantProfileRoutes()` pattern; `[...slug].astro` catch-all serves all routes |
| Empty state UX | Step 4 includes `emptyMessage` prop in the `nachweis-list` block configuration |
| Component reusability | Step 2 components accept `verifiedByLabel` prop from block config; Step 4 page entries pass the site name via props |
| Pilot content in preview indefinitely | Step 6 creates records with `publication.visibility: preview`; `getNachweisRoutes()` excludes preview records from route generation |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-17 (Mirror Quintet), run `rfc.supersede.propose --id RFC-0708 --reason "..." --invariant "DNA-17"` instead of working around it.
- If the `nachweis` entitlement cannot be resolved (RFC-0707 not yet implemented), block Step 4 entitlement activation and document the dependency.
- If `archetype.registry.build` fails to discover the new manifests, check that manifest `cosmicName` values match `MoonCatalog` entries and are not passport-reserved.
