### Step 3. Implement transitive skip algorithm and cross-pipeline persistence in pipeline executor

**Goal:** Add `PipelineRunState`, `shouldTransitiveSkip`, `loadImportedCacheHits`, `persistCacheHits` to `execute-pipeline.ts` and integrate into both `executePipelineForSite` and `executePipelineForWorkspace`.

**Agent actions:**

- Add `PipelineRunState` interface with `cacheHitCommands: Set<string>` and `pipelineName: string`
- Add `shouldTransitiveSkip(command, runState)` function: returns `false` if `cacheable === false`, `false` if no `validatesOutputs`, otherwise checks all entries in `cacheHitCommands`
- Add `PIPELINE_CACHE_HITS_PATH`, `PIPELINE_CACHE_HITS_STALENESS_MS` constants
- Add `PipelineCacheHitsFile` interface
- Add `loadImportedCacheHits(workspaceRoot, currentPipelineName)` function: reads `.cache/pipeline-cache-hits.json`, merges non-stale entries (within 30-minute TTL) from pipelines other than `currentPipelineName`, returns `Set<string>`. Handles missing/corrupt file gracefully (returns empty set).
- Add `persistCacheHits(workspaceRoot, pipelineName, cacheHitCommands)` function: writes `cacheHitCommands` under `pipelineName` in `.cache/pipeline-cache-hits.json`, replacing any previous entry for that pipeline. Preserves entries for other pipelines.
- In `executePipelineForSite` (line 425+):
  - Create `cacheHitCommands` set from `loadImportedCacheHits` at start
  - Before `tryCacheRead`, check `shouldTransitiveSkip(command, runState)` — if true, create a skipped report with `skipReason: "transitive-cache-skip"` and add command to `cacheHitCommands`
  - After `tryCacheRead` returns a cache hit, add command name to `cacheHitCommands`
  - After pipeline run completes, call `persistCacheHits`
  - If `--force`, clear `.cache/pipeline-cache-hits.json` before run and skip all transitive-skip checks
- In `executePipelineForWorkspace` (line 449+): same integration as `executePipelineForSite`
- Add `--force` handling: clear `.cache/pipeline-cache-hits.json` file before the run starts

**Validation:**

- `pnpm --filter @warpgogol/site-kernel run build:check` — TypeScript compiles without errors
- Manual review: verify `shouldTransitiveSkip` checks `cacheable !== false` before `validatesOutputs`

**Completion criterion:** `shouldTransitiveSkip` function exists and correctly checks `cacheable !== false` + `validatesOutputs` + `cacheHitCommands`; `loadImportedCacheHits` and `persistCacheHits` functions exist; both pipeline executors integrate transitive skip; `--force` clears the persistence file; `build:check` passes.

**Human review:** no

### Step 4. Write unit tests for transitive skip logic

**Goal:** Comprehensive unit tests covering all transitive skip scenarios from acceptance criteria.

**Agent actions:**

- Create `packages/os/site-kernel/src/tests/transitive-skip.test.ts`
- Test cases:
  - (a) Transitive skip fires when all upstream cached — `shouldTransitiveSkip` returns `true` when all `validatesOutputs` entries are in `cacheHitCommands`
  - (b) No skip when upstream cache miss — `shouldTransitiveSkip` returns `false` when at least one entry is missing
  - (c) No skip for `cacheable: false` validators — `shouldTransitiveSkip` returns `false` when `command.cacheable === false`
  - (d) Transitive skip through a chain of 2 validators — validator B skips when both generator G and validator A are in `cacheHitCommands`
  - (e) `--force` disables transitive skip — `cacheHitCommands` is empty, `shouldTransitiveSkip` returns `false`
  - (f) Stale `.cache/pipeline-cache-hits.json` entries (>30 min) are ignored — `loadImportedCacheHits` skips entries with `writtenAt` older than 30 minutes
  - (g) Cross-pipeline skip works — `loadImportedCacheHits` merges entries from other pipelines into `cacheHitCommands`
  - (h) No skip when `validatesOutputs` is empty or undefined — `shouldTransitiveSkip` returns `false`
  - (i) Corrupt `.cache/pipeline-cache-hits.json` falls back to empty set — `loadImportedCacheHits` handles JSON parse errors gracefully
  - (j) `persistCacheHits` preserves entries for other pipelines — writing `build.check` entry does not overwrite `build.prepare` entry

**Validation:**

- `pnpm --filter @warpgogol/site-kernel run build:check` — tests pass

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| False-negative on manual edits | Step 3: `shouldTransitiveSkip` checks `cacheable !== false`; `generated.drift.validate` (cacheable: false) always runs and catches drift (safety net) |
| Incorrect `validatesOutputs` declaration | Step 3: `shouldTransitiveSkip` checks `cacheable !== false`; no validators annotated in this RFC (infrastructure-only); `cacheable: false` validators catch missing/stale files |
| No cacheable generator→validator pairs exist | Step 4: unit tests use mock commands with `validatesOutputs` to verify the mechanism works; no production annotations needed |
| Agent misinterpretation (replacing `reads[]`) | Step 6: AGENTS.md documents that `validatesOutputs` is NOT a replacement for `reads[]` |
| Stale `.cache/pipeline-cache-hits.json` | Step 3: 30-minute TTL in `loadImportedCacheHits`; Step 5: test case (f) verifies stale entries are ignored |
| RFC-0686 concurrent execution | Step 3: `cacheHitCommands` updated after each step completes; documented in AGENTS.md that parallel steps must update after wave completion |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-35 or DNA-53, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0687 --reason "..." --invariant "DNA-N"` instead of working around it.
- If `shouldTransitiveSkip` is found to be insufficient for a cacheable validator that reads both generated and authored files, do not add a `reads[]` hash check back — instead, remove `validatesOutputs` from that validator and rely on the normal cache check.
