## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Caller migration introduces bugs (wrong `systemId`, missing `actor`) | Steps 4–6: each caller migrated one file at a time with `build:check` after each |
| `bordbuch.generate` projection shape differs from old `bordbuchStatusSchema` | Step 3: rich projection preserves PSEO modules, visibility, stellarpass, deploy |
| `generator-ownership.ts` path change breaks ownership lint | Step 8: update `generator-ownership.ts` in same change as path change |
| Public projection path change breaks external consumers | Step 8: URL path `/bordbuch.json` unchanged; only source directory changes |
| `bordbuchEntryKindSchema` enum extension breaks existing validators | Step 1: adding enum values is backward-compatible; existing entries remain valid |
| `site.bordbuch.validate` removal breaks pipeline before `bordbuch.validate` is wired | Step 8: pipeline update and command removal in same change |
| Runtime events flood the Sternsystem Bordbuch | No mitigation needed: volume unchanged from old code |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-46, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0473 --reason "..." --invariant "DNA-46"` instead of working around it (RFC-0334).
- If `bordbuch.generate` cannot access PSEO module context from `site-kernel-handoff` (package boundary issue), consider moving the PSEO context reading into a shared helper or keeping the generate command in `site-kernel-checks` — but only if the package boundary is truly impassable. Prefer keeping it in `site-kernel-handoff` per the RFC.
