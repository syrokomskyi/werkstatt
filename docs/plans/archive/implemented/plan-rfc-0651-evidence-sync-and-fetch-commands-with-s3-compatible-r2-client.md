# Implementation Plan: RFC-0651

## 1. Objectives

- [ ] Objective 1 — `evidence.sync` command uploads evidence artifacts to R2 — maps to acceptance criterion "evidence.sync --mission <id> uploads all files from evidence/axiom/ to R2"
- [ ] Objective 2 — `evidence.fetch` command downloads historical runs and lists available runs — maps to acceptance criteria "evidence.fetch --mission <id> --run-timestamp <ts> --output-dir <dir>" and "evidence.fetch --list"
- [ ] Objective 3 — `evidence.sync --dry-run` reports without R2 API calls — maps to acceptance criterion "evidence.sync --dry-run"
- [ ] Objective 4 — Failure modes produce correct diagnostics (`MISSING_ENV`, `INVALID_EVIDENCE`, `NOT_FOUND`, `R2_UPLOAD_ERROR`, `R2_LIST_ERROR`) — maps to acceptance criteria for each diagnostic
- [ ] Objective 5 — Command registration, module wiring, and manifest generation — maps to acceptance criteria "evidence.sync command registered", "evidence.fetch command registered", "command.manifest.generate run"
- [ ] Objective 6 — `.env.example` documents R2 environment variables — maps to acceptance criterion ".env.example documents R2_ACCOUNT_ID..."

### Step 3. Implement `evidence-sync.ts` — `evidence.sync` command handler

**Goal:** Upload all evidence artifacts from `missions/{mission}/evidence/axiom/` to R2 under `{systemId}/{missionId}/{runTimestamp}/` prefix.

**Agent actions:**

- Create `packages/os/site-kernel-handoff/src/evidence/evidence-sync.ts`
- Implement `runEvidenceSync(input, context)` following the `EvidenceSyncInput`/`EvidenceSyncResult` contracts from the RFC
- Resolve `systemId` from `systems/registry.yaml` by matching `missionId` to the active mission
- Read `runTimestamp` from `evidence-metadata.json` (fall back to `--run-timestamp` flag, then error with `INVALID_EVIDENCE`)
- Walk `evidence/axiom/` recursively, upload each file with `putObject`
- Support `--dry-run`: list files that would be uploaded without making R2 API calls
- Return `EvidenceSyncResult` with `uploadedFiles`, `skippedFiles`, `totalBytes`, `durationMs`
- Build `KernelCommandResult` manually (not `passResult`/`failResult`) since the return type is custom

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-handoff run build:check` passes

**Completion criterion:** `evidence-sync.ts` compiles, handles `--dry-run`, reads `runTimestamp` from `evidence-metadata.json`, and returns the correct result shape.

**Human review:** no

### Step 4. Implement `evidence-fetch.ts` — `evidence.fetch` command handler

**Goal:** Download a historical run from R2 and list available runs via `ListObjectsV2`.

**Agent actions:**

- Create `packages/os/site-kernel-handoff/src/evidence/evidence-fetch.ts`
- Implement `runEvidenceFetch(input, context)` following the `EvidenceFetchInput`/`EvidenceFetchResult`/`EvidenceListResult` contracts
- When `--list`: call `listObjectsV2` with prefix `{systemId}/{missionId}/`, parse run timestamps from keys, download `evidence-metadata.json` for each run to extract `commitSha`
- When fetching (no `--list`): download all objects under `{systemId}/{missionId}/{runTimestamp}/` to `--output-dir`, skip `raw/` if `--no-raw`
- Handle `NOT_FOUND` when run not found in R2
- Handle `R2_LIST_ERROR` when `ListObjectsV2` fails
- Build `KernelCommandResult` manually

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-handoff run build:check` passes

**Completion criterion:** `evidence-fetch.ts` compiles, handles `--list` and fetch modes, supports `--no-raw`, and returns the correct result shapes.

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| No SQL queryability in initial implementation | Step 4 uses `ListObjectsV2` as primary; Iceberg deferred per RFC nonGoal. A future RFC can add SQL. |
| R2 credentials management | Step 8 documents env vars in `.env.example`; Step 10 AGENTS.md states agents MUST NOT hardcode credentials. `.env` is gitignored. |
| Upload time (~17s per run) | Not a plan concern — `evidence.sync` is standalone. RFC-0652 integrates as best-effort, non-blocking in `leitstand.dev-deploy`. |
| Agent misinterpretation (auto-sync after mission.check) | Step 10 AGENTS.md documents the policy: agents MUST NOT invoke `evidence.sync` independently unless explicitly asked. |
| Cost of R2 Class A operations | Negligible (~$0.08/month per RFC). No mitigation needed. |
| SDK bundle size (~2 MB) | Acceptable for Node.js-only package. Step 1 adds the dependency; no client-side impact. |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-52 or DNA-59, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0651 --reason "..." --invariant "DNA-N"` instead of working around it (RFC-0334).
- If `@aws-sdk/client-s3` proves incompatible with R2's S3 endpoint, escalate to the operator — do not switch to `wrangler r2` CLI without an RFC amendment.
- If `ListObjectsV2` does not return sufficient metadata for the `--list` output (e.g., `commitSha` not available without downloading `evidence-metadata.json`), document the N+1 download cost in the implementation commit and proceed — the RFC already accounts for this in Alternative 3.
