**Goal:** Add SNAP-01 auto-recovery to `runBehaviorSnapshotValidate` in `behavior-snapshot.ts`.

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| `release.ready` rename breaks existing scripts | Step 8 migrates existing releases; Step 9 updates all docs. Clean break is intentional. |
| Auto-recovery masks real issues | Step 5 logs a warning when auto-recovery triggers. Operators must review the diff. |
| Retry loop adds ~45s latency | Step 3 reuses existing RFC-0657 constants (5 attempts, 4 delays). Acceptable vs wrong-version deploy. |
| Axiom gate adds ~5 min to release path | Step 3 calls `runMissionCheckWithResilience` with existing timeout/retry. Cost of live verification. |
| Concurrent `mission.validate` bordbuch auto-commit | Step 6 uses `commitBordbuchProjections` which uses `gitExecWithRetry` with backoff. Non-fatal on failure. |

## 6. Escalation triggers

- If the `published` → `ready` rename reveals additional state references not identified in the plan, extend the rename to all discovered locations. Do not add backward compat aliases.
- If `verifyFreshness` cannot be exported from `leitstand-commands.ts` due to circular import issues, extract it to a shared file in the same package (not a new package).
- If `runMissionCheckWithResilience` cannot be called from the release path because `missionId` is missing from the release manifest, throw a clear error directing the operator to ensure `releaseManifest.missionId` is set.
