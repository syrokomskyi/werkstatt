## 3. Step sequence

### Step 1. Create pure function + thin kernel handler

**Goal:** Implement `dist-html-structure.ts` with the tag-balance checking logic as a pure function, wrapped by a thin kernel handler.

**Agent actions:**

- Create `packages/os/site-kernel-checks/src/dist-html-structure.ts`
- Define `STRUCTURAL_TAGS` as `const readonly string[]`: `main`, `header`, `nav`, `footer`, `section`, `article`, `aside`, `body`, `head`, `form`, `figure`, `details`, `dialog`, `template`
- Define `HtmlStructureViolation` interface: `{ file, rule, tag, openCount, closeCount, message }`
- Define `HtmlStructureValidateResult` interface: `{ command, status, filesScanned, violations? }`
- Implement pure function `checkHtmlStructure(htmlContent: string): HtmlStructureViolation[]`:
  - Step 0: Strip HTML comments (`<!-- ... -->`) using regex `<!--[\s\S]*?-->` replaced with empty string
  - For each structural tag: count openings via `<tag\b[^>]*>` (excluding `</tag>`), count closings via `</tag>`
  - If `openCount !== closeCount`, emit violation with `rule: "HTML-STRUCT-01"`
- Implement thin kernel handler `runDistHtmlStructureValidate(input, context)`:
  - Resolve app from `context.site?.name ?? input.flags.site`
  - Resolve `distClient` path from `context.site?.directory ?? join(context.workspaceRoot, "apps", app)` + `dist/client`
  - If `dist/client` missing: return `passResult` with skip message (same pattern as `dist.generated-marker.validate`)
  - Walk `.html` files via `collectFiles` from `@warpgogol/share/fs`
  - For each file: read content, call `checkHtmlStructure`, collect violations with relative file path
  - If violations: return fail result with `exitCode: 1` and `violations[]`
  - If no violations: return pass result with `filesScanned` count
- Add Compass `MODULE_CONTRACT` and `CHANGE_SUMMARY` headers (DNA-42)
- Import `passResult` from `./result-helpers.ts`
- Import `collectFiles` from `@warpgogol/share/fs`

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-checks run build` — TypeScript compiles without errors

**Completion criterion:** File `packages/os/site-kernel-checks/src/dist-html-structure.ts` exists, exports `runDistHtmlStructureValidate` and `checkHtmlStructure`, TypeScript compiles.

### Step 4. Write unit tests

**Goal:** Comprehensive unit tests for the pure function and kernel handler.

**Agent actions:**

- Create `packages/os/site-kernel-checks/src/tests/dist-html-structure.test.ts`
- Test cases for pure function `checkHtmlStructure`:
  1. **Balanced HTML passes**: `<html><body><main></main></body></html>` → no violations
  2. **Missing opening tag fails**: `</main>` without `<main>` → violation with `openCount: 0, closeCount: 1`
  3. **Missing closing tag fails**: `<main>` without `</main>` → violation with `openCount: 1, closeCount: 0`
  4. **Void elements ignored**: `<br><img><input>` → no violations (not in structural tag list)
  5. **HTML comments with tag-like strings do not cause false positives**: `<!-- <main> -->` → no violations (comment stripped before counting)
  6. **Multiple structural tags checked**: `<header><nav></nav></header><main></main>` → no violations
  7. **Self-closing variant counted as opening**: `<main />` → `openCount: 1` (browsers treat as opening)
  8. **Multiple violations in one file**: missing `<main>` and missing `</header>` → 2 violations
- Test cases for kernel handler `runDistHtmlStructureValidate`: 9. **No dist/client directory**: returns pass result with skip message 10. **Clean build passes**: temp dir with balanced HTML files → `status: "pass"`, `filesScanned > 0` 11. **Violations detected**: temp dir with imbalanced HTML → `exitCode: 1`, `violations[]` populated 12. **--json output shape**: result `data` matches `HtmlStructureValidateResult` interface
- Use `vi.mock` or temp directories for handler tests (follow existing test patterns in `src/tests/`)
- Test helper for extracting violations from result data: accept `unknown` and cast internally (per established pattern)

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-checks run test -- --run dist-html-structure` — all tests pass

**Completion criterion:** All 12 test cases pass.

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| False positives from HTML comments | Step 1: comment stripping regex `<!--[\s\S]*?-->` before counting; Step 4: test case 5 verifies |
| False positives from attribute values | Step 4: test case 7 documents the trade-off; accepted as unlikely per RFC Risks section |
| Performance (1518 files) | Step 1: O(n) regex per file, ~14 tags; Step 5: verify <1s on real site |
| Agent misinterpretation (accessibility vs tag balance) | Step 6: AGENTS.md entry clarifies "tag balance, not accessibility landmarks" |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-8 or DNA-35, run `pnpm exec site-kernel run rfc.supersede.propose --id RFC-0654 --reason "..." --invariant "DNA-N"` instead of working around it.
- If the comment stripping regex proves insufficient for real-world HTML (e.g. conditional comments, nested comments), escalate to a full HTML parser approach (Alternative 2 in the RFC) via a new RFC rather than patching the regex incrementally.
