### Step 2. Command handler: remove `runLeitstandDeploy`, add `runLeitstandDevDeploy`

**Goal:** Replace the release-based `leitstand.deploy` handler with a workpiece-based `leitstand.dev-deploy` handler that builds from workpiece, deploys to dev, runs Axiom, and post-processes evidence capsule with `commitSha`.

**Agent actions:**

- In `leitstand-commands.ts`:
  - Remove `runLeitstandDeploy` function and `LeitstandDeployData` interface.
  - Add `DevDeployResult` interface with fields: `command`, `systemId`, `missionId`, `commitSha`, `buildState`, `deployState`, `axiomStatus`, `axiomErrors`, `axiomWarnings`, `axiomExitCode`, `deploymentUrl`.
  - Add `runLeitstandDevDeploy` function that:
    1. Reads `--system` flag, resolves `currentMission` from registry, resolves workpiece path `missions/{mission}/workpiece/`.
    2. Runs `pnpm build` in workpiece directory via `execSync` (or `child_process.exec`). If build fails, return exit 1.
    3. Captures workpiece HEAD SHA via `git rev-parse HEAD` in workpiece directory.
    4. Reads dev channel config from registry (`deployment.channels.dev`).
    5. Resolves secrets via `resolveSecretsFilePath(channelConfig.secretsFile)` — same as current `leitstand.deploy`.
    6. Calls `adapter.propagate()` with workpiece `dist/` path.
    7. Purges CDN cache via `runPurgeStep` (same as existing commands, RFC-0624).
    8. Runs health check via `adapter.health()`.
    9. Invokes `mission.check --external-preview --base-url <dev-url> --mission <missionId>` via `executeKernelCommand`.
    10. Post-processes `evidence-capsule.yaml`: reads it, adds `commitSha` field, writes back. Uses `writeFileIfChanged`.
    11. Does NOT call `writeRegistry`, `appendBordbuchEntry`, or `writeReleaseYaml`.
    12. Returns `DevDeployResult` with all status fields.
- Remove `LeitstandDeployData` interface and all references to `runLeitstandDeploy`.

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-handoff run build:check` passes.
- `grep -r "runLeitstandDeploy" packages/os/site-kernel-handoff/src/` returns no results.

**Completion criterion:** `runLeitstandDevDeploy` exists, `runLeitstandDeploy` is deleted, and the new handler does not write to registry or bordbuch.

**Human review:** no

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| `leitstand.propagate` evidence `commitSha` mismatch | Step 3: gate checks `commitSha` match with actionable error message directing to re-run `leitstand.dev-deploy` |
| Dirty workpiece HEAD sha | Step 2: captures HEAD sha regardless of dirty state; implementation notes specify operator must commit + re-deploy before release |
| `mission.check` failure (Playwright missing) | Step 2: passes through exit code 4; implementation notes specify `pnpm exec playwright install chromium` |
| Test fixture breakage from schema change | Step 6: all registry fixtures updated to remove `dev-deployed` references; mock `isWorkpieceDirty` directly |
| `command-manifest.generated.yaml` stale | Step 9: `command.manifest.generate` run after module changes |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-48 or DNA-49, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0628 --reason "..." --invariant "DNA-N"` instead of working around it.
- If `leitstand.propagate` gate cannot be changed without breaking existing releases (e.g., a release is already in `dev-deployed` state), stop and report to the operator — the RFC assumes clean slate (no release has entered `dev-deployed` in production).
