### Step 5. Add `orderTags` to FAQ schema and update sort logic

**Goal:** Add the `orderTags` field to `faqSchema` and update `getFaqEntriesByTags` to use per-tag ordering.

**Agent actions:**

- Edit `packages/faq/src/schema.ts`: add `orderTags: z.record(z.string(), z.number()).optional()` to `faqSchema` (after `tags`)
- Edit `packages/faq/src/astro.ts`: update `getFaqEntriesByTags` to sort by `orderTags[tags[0]]` with fallback to `order`:

```ts
export async function getFaqEntriesByTags(lang: string, tags: string[]): Promise<FaqEntry[]> {
  const all = await getFaqEntries(lang);
  const tag = tags[0]; // primary queried tag — caller passes tags in priority order
  return all
    .filter((e) => e.tags?.some((t) => tags.includes(t)))
    .sort((a, b) => {
      const aOrder = a.orderTags?.[tag] ?? a.order ?? 999;
      const bOrder = b.orderTags?.[tag] ?? b.order ?? 999;
      return aOrder - bOrder;
    });
}
```

**Validation:**

**Completion criterion:** `build:check` passes; `orderTags` is in `faqSchema`; `getFaqEntriesByTags` uses `orderTags[tags[0]]` with fallback to `order`.

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Eyebrow overuse — available to all sections may lead to inconsistent usage | Step 2 renders it as optional; RFC implementation notes say "expert-file-driven" |
| `orderTags` complexity — content authors must understand the map structure | Step 6 documents the field and behavior in `packages/faq/AGENTS.md`; fallback to `order` simplifies adoption |
| Agent misinterpretation — agents may add `eyebrow` to every section | RFC implementation notes explicitly say MUST NOT; plan does not add `eyebrow` to any existing content |
| No performance impact | N/A — schema validation is build-time; sort is O(n log n) with map lookup |
