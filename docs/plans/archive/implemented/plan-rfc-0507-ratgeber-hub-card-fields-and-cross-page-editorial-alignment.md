### Step 3. Add RG-HUB-09 to `ratgeber.hub.validate`

**Goal:** Add a warning-level rule that detects `description` keys in hub page card props.

**Agent actions:**

- Edit `packages/os/site-kernel-checks/src/ratgeber-hub-validate.ts`: after RG-HUB-08, add RG-HUB-09.
- Logic: for the hub entry (depth-0, `surfaceId: ratgeber`), iterate `page.blocks`. For each block with `type: "audience-cards"`, check `props.body.cards[]`. If any card has a `description` key, emit a warning diagnostic with `ruleId: "RG-HUB-09"`, `severity: "warning"`.

**Validation:**

- `pnpm --filter @gogol/site-kernel-checks run build:check` — typecheck passes.
- `pnpm exec werkstatt run ratgeber.hub.validate --mission warpgogol-com-m000010` — passes (no warnings after Step 2 removes `description`).

**Completion criterion:** RG-HUB-09 fires a warning when a hub card contains `description`, and passes cleanly after Step 2.

**Human review:** no

### Step 4. Add VOICE-CTA-01 to `content.voice.lint`

**Goal:** Add a warning-level rule that detects markdown price tables (3+ data rows with price patterns) in ratgeber article pages.

**Agent actions:**

- Edit `packages/os/site-kernel-checks/src/content-voice.ts`: add VOICE-CTA-01 check.
- Logic: for each ratgeber article page (depth-1, `surfaceId: ratgeber`), scan `blocks` for `type: "markdown"`. In the markdown content, detect markdown tables (lines starting with `|`). Count data rows (exclude header + separator rows). If 3+ data rows and any cell matches price pattern (`€`, `EUR`, `{business-profile...price...}`), emit warning with `ruleId: "VOICE-CTA-01"`, `severity: "warning"`.

**Validation:**

- `pnpm --filter @gogol/site-kernel-checks run build:check` — typecheck passes.
- `pnpm exec werkstatt run content.voice.lint --mission warpgogol-com-m000010` — passes or warns only on legitimate price tables.

**Completion criterion:** VOICE-CTA-01 fires a warning on ratgeber article pages with 3+ row price tables, and does not fire on articles with inline calculations only.

**Human review:** no

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Editorial drift on /leistungen/, /website/, /notausgang/ | Steps 7–9 flag content changes for human review; claim registry (RFC-0505) provides traceable IDs |
| Footer link removal without redirect | Step 6 only moves links between groups; Widerruf links already removed by RFC-0487 |
| Agent misinterpretation of "remove or soften" | Steps 7–9 list specific claims to remove; flag for operator review |
| RG-HUB-09 false positives | Step 3 scopes rule to hub page (depth-0, surfaceId: ratgeber) only |
| VOICE-CTA-01 false positives | Step 4 uses warning severity; requires both table + price pattern match |
| Footer component breaking other sites | Step 5 guards Transparenz group with `transparencyLinks.length > 0` check |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-16 (semantic layer shares topology with navigation), run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0507 --reason "..." --invariant "DNA-16"` instead of working around it.
- If the footer component change requires a new component manifest cosmic name, escalate to `section.scaffold` rather than hand-editing the manifest.
- If the website-local blueprint change reveals a surface contract conflict, escalate to a new RFC rather than modifying the blueprint contract.
