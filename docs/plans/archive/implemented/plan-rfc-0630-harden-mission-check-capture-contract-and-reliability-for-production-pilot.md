## 3. Step sequence

### Step 1. Add `createRequire` import and runtime toolProfile resolution

**Goal:** Replace hardcoded `toolProfile` stubs with runtime values from `playwright/package.json`, `crawlee/package.json`, and `browser.version()`.

**Agent actions:**

- Add `import { createRequire } from "node:module"` at top of `mission-check.ts`
- Create `const require = createRequire(import.meta.url)` at module level
- Add `resolveToolProfile()` function that:
  - Reads `playwrightVersion` from `require("playwright/package.json").version` in try/catch, fallback `"unknown"`
  - Reads `crawleeVersion` from `require("crawlee/package.json").version` in try/catch, fallback `"unknown"`
  - Returns `{ crawleeVersion, playwrightVersion, chromiumRevision: "unknown" }` (chromiumRevision updated after first capture)
- Modify `buildCaptureContract()` to accept a `toolProfile` parameter instead of hardcoding stubs
- After first successful `driver.capture()`, extract `browser.version()` from the Playwright browser instance via `driver.getBrowserVersion()` (new method on `PlaywrightEvidenceDriver` or accessible via the driver's internal browser) — wrap in try/catch, fallback `"unknown"`
- Update `buildStagedCapsule()` to use the runtime toolProfile values for `runtimeAttestation.toolDigests`

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-checks run build:check` passes
- `staged-capsule.json` `runtimeAttestation.toolDigests` contains real values (not `"unknown"`/`"local-dev"`) when packages are installed

**Completion criterion:** `buildCaptureContract()` no longer contains hardcoded `"unknown"` or `"local-dev"` for toolProfile fields; `resolveToolProfile()` function exists and is called; try/catch fallbacks are in place.

**Human review:** no

### Step 2. Raise `maxDurationMs` default and add CLI flag parsing

**Goal:** Increase discovery deadline from 30s to 120s and parse `--max-duration`, `--max-urls`, `--max-depth`, `--locales` flags.

**Agent actions:**

- Change `maxDurationMs: 30_000` to `maxDurationMs: 120_000` in `buildCaptureContract()`
- Modify `buildCaptureContract()` signature to accept `MissionCheckOverrides` (optional `maxDuration`, `maxUrls`, `maxDepth`, `locales`)
- In `runMissionCheck()`, parse overrides from `input.flags`:
  - `--max-duration` → `maxDuration` (number)
  - `--max-urls` → `maxUrls` (number)
  - `--max-depth` → `maxDepth` (number)
  - `--locales` → `locales` (string, comma-separated, parsed to `string[]`)
- Validate `--locales` format: if provided, must match BCP 47 pattern `^[a-z]{2}-[A-Z]{2}(,[a-z]{2}-[A-Z]{2})*$`; exit code 2 on invalid format
- Apply overrides to contract fields: `limits.maxDurationMs`, `limits.maxUrls`, `urlPolicy.maxDepth`, `locales`

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-checks run build:check` passes
- Unit test: `buildCaptureContract` with no overrides returns `maxDurationMs: 120000`
- Unit test: `buildCaptureContract` with `maxDuration: 180000` returns `maxDurationMs: 180000`

**Completion criterion:** `maxDurationMs` default is 120000; all 4 flags are parsed from `input.flags` and override contract defaults; invalid `--locales` format exits with code 2.

**Human review:** no

### Step 3. Implement i18n locale resolution from mission workpiece

**Goal:** Read `i18n.supported` from `missions/<missionId>/workpiece/src/content/system.md` and build a language-to-locale mapping for page-language matching.

**Agent actions:**

- Import `loadI18nConfigSync` from `@warpgogol/site-kernel-content` (or read `system.md` frontmatter directly using `loadSystemManifestSync`)
- Add `resolveLocaleMapping(missionDir: string)` function that:
  - Reads `missions/<missionId>/workpiece/src/content/system.md`
  - Parses `i18n.supported` map (e.g., `{ de: { name: "Deutsch", hreflang: "de-DE" }, uk: { name: "Українська", hreflang: "uk-UA" } }`)
  - Returns `Map<string, string>` mapping path segment (e.g., `"de"`) to hreflang locale (e.g., `"de-DE"`)
  - Falls back to `new Map([["en", "en-US"]])` if no `i18n` section, with a warning log
- Add `resolveLocaleForUrl(url: string, localeMap: Map<string, string>, defaultLocale: string): string` function that:
  - Extracts the first path segment from the URL (e.g., `/de/leistungen` → `de`)
  - Looks up the segment in `localeMap`; returns the matching hreflang
  - Falls back to `defaultLocale` (from `i18n.default` hreflang) if segment not found
  - Falls back to `"en-US"` if no i18n config

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-checks run build:check` passes
- Unit test: `resolveLocaleMapping` with a workpiece containing `i18n.supported: { de: { hreflang: "de-DE" }, uk: { hreflang: "uk-UA" } }` returns `Map([["de", "de-DE"], ["uk", "uk-UA"]])`
- Unit test: `resolveLocaleForUrl("https://example.com/de/leistungen", map, "de-DE")` returns `"de-DE"`
- Unit test: `resolveLocaleForUrl("https://example.com/uk/kontakty", map, "de-DE")` returns `"uk-UA"`
- Unit test: `resolveLocaleForUrl("https://example.com/impressum", map, "de-DE")` returns `"de-DE"` (fallback to default)

**Completion criterion:** `resolveLocaleMapping` and `resolveLocaleForUrl` functions exist, are tested, and correctly map URL path segments to hreflang locales with proper fallbacks.

**Human review:** no

### Step 4. Implement page-language matching in capture loop

**Goal:** Use the locale mapping to set the correct browser locale for each page's capture.

**Agent actions:**

- In `runMissionCheck()`, after resolving the mission dir, call `resolveLocaleMapping(missionDir)` to get the locale map
- If `--locales` flag is provided, skip auto-detection and use the explicit locale list for all pages
- If `--locales` is not provided, for each `discoveredUrl` in the capture loop:
  - Call `resolveLocaleForUrl(pageUrl, localeMap, defaultLocale)` to get the per-page locale
  - Pass this locale in the `capture()` request: `request: { url: pageUrl, profileId: ..., locale: resolvedLocale }`
  - Use the same resolved locale in the `axeStates` entry
- The capture contract's `locales` array should contain all unique locales from the mapping (for contract provenance), but each capture uses its specific locale

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-checks run build:check` passes
- Unit test: mock `CrawleeDiscoveryExecutor` returns URLs with `/de/` and `/uk/` segments; verify `PlaywrightEvidenceDriver.capture` is called with `locale: "de-DE"` for `/de/` URLs and `locale: "uk-UA"` for `/uk/` URLs
- Unit test: with `--locales de-DE,uk-UA` flag, all captures use `de-DE` (first locale) — or the contract specifies both and each page gets the first matching locale

**Completion criterion:** Each page's capture request carries the locale matching its URL path segment; `--locales` flag overrides auto-detection.

**Human review:** no

### Step 5. Add Playwright pre-flight check

**Goal:** Before discovery, verify chromium is installed by launching and closing a browser.

**Agent actions:**

- Add `runPreflightCheck(): Promise<PreflightResult>` function that:
  - Imports `chromium` from `playwright`
  - Calls `chromium.launch({ headless: true })` + `browser.close()`
  - Returns `{ ok: true }` on success
  - Returns `{ ok: false, error: "mission.check: Playwright chromium not installed. Run 'npx playwright install chromium' and retry." }` on failure
- In `runMissionCheck()`, after flag parsing and before discovery:
  - Call `runPreflightCheck()`
  - If `!result.ok`, return `failResult(evidenceDir, 2, result.error)`

**Validation:**

- `pnpm --filter @warpgogol/site-kernel-checks run build:check` passes
- Unit test: mock `chromium.launch` to throw; verify `runMissionCheck` returns exit code 2 with the actionable message
- Unit test: mock `chromium.launch` to succeed; verify discovery proceeds

**Completion criterion:** Pre-flight check runs before discovery; exit code 2 with actionable message on failure; discovery proceeds on success.

**Human review:** no

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| `createRequire(import.meta.url)` may fail in bundled contexts | Step 1: wrap in try/catch, fallback to `"unknown"` |
| i18n resolution depends on `system.md` format | Step 3: fallback to `["en-US"]` with warning log |
| Page-language matching assumes URL path segments | Step 4: `--locales` flag allows explicit override for content-negotiation sites |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-48 or DNA-49, run `pnpm exec site-kernel run rfc.supersede.propose --id RFC-0630 --reason "..." --invariant "DNA-N"` instead of working around it.
- If `createRequire(import.meta.url)` cannot resolve `playwright/package.json` or `crawlee/package.json` even in non-bundled context (pnpm workspace isolation), escalate — this may require adding `playwright` and `crawlee` as direct dependencies of `@warpgogol/site-kernel-checks`, which would be a package boundary change requiring a separate RFC.
