**Goal:** Extend `service.naming.validate` with a rule that rejects service ids ending with `-worker`.

**Agent actions:**

- Read `packages/werkstatt-site/src/checks/services/service-naming-validate.ts`
- Add SVC-NAME-06 check inside the `for (const service of services)` loop, after the existing SVC-NAME-01 check: if `id.endsWith("-worker")`, emit a diagnostic with `ruleId: "SVC-NAME-06"`, `severity: "error"`, `file: "services/registry.yaml"`, `message: "Service '<id>': id must not end with '-worker' suffix. Rename to '<id-without-suffix>'."`

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Broken workspace symlinks after directory rename | Step 3 runs `pnpm install` immediately after `git mv` |
| Cloudflare Worker URL changes break external integrations | Step 4 updates `url` fields in registry; old Workers deleted in Phase 2 (operational, not code) |
| Hardcoded references missed | Step 5 runs `grep -rn` to find all references; Step 7 runs validators to catch any remaining mismatches |
| Test fixtures break from SVC-NAME-06 rule | Step 2 updates test fixtures before the rename |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-N, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0805 --reason "..." --invariant "DNA-N"` instead of working around it.
- If `service.naming.validate` reports violations that cannot be resolved by the rename (e.g. a fourth service with `-worker` suffix not listed in the RFC), investigate before proceeding.
