## 3. Step sequence

### Step 1. Add `autoDetectImplementationCommit` helper

**Goal:** Create the git-based auto-detection function that enumerates commits referencing the RFC ID.

**Agent actions:**

- Add `autoDetectImplementationCommit(workspaceRoot: string, rfcId: string): Promise<{ sha: string } | { multiple: Array<{ sha: string; message: string }> } | { none: true }>` to `packages/forge/os/rfc/handlers/implement-stamp.ts`
- Implementation: run `git log --fixed-strings --no-merges --grep="<RFC-ID>" --format=%H` via `execGit`
- Parse output: split by newline, filter empty lines
- If 0 results → return `{ none: true }`
- If 1 result → return `{ sha: <hash> }`
- If >1 results → fetch short SHAs and messages via `git log --fixed-strings --no-merges --grep="<RFC-ID>" --format="%h %s"` and return `{ multiple: [...] }`

**Validation:**

- `pnpm --filter @warpgogol/forge run build:check` — typecheck passes

**Completion criterion:** `autoDetectImplementationCommit` function exists, is typed, and typechecks. It is not yet wired into the handler flow.

**Human review:** no

### Step 2. Make `--implementation-commit` optional in handler and module

**Goal:** Change the flag from required to optional and wire auto-detect into the handler flow.

**Agent actions:**

- In `packages/forge/os/rfc/handlers/implement-stamp.ts`:
  - Remove the `if (!implementationCommit) { throw ... }` block (lines 202-206)
  - After flag validation and before RFC-IMP-03 checks, add: if `implementationCommit` is not set, call `autoDetectImplementationCommit(workspaceRoot, targetId)`
  - If result is `{ none: true }` → push `RFC-IMP-03` violation: "No commit referencing `<RFC-ID>` found in git history. Pass `--implementation-commit <SHA>` explicitly."
  - If result is `{ multiple: [...] }` → push `RFC-IMP-03` violation: "Multiple commits reference `<RFC-ID>`: <list of short SHA + message>. Pass `--implementation-commit <SHA>` to specify which one."
  - If result is `{ sha }` → set `implementationCommit = sha`
- In `packages/forge/os/rfc/rfc.module.ts`:
  - Change `"implementation-commit"` flag from `required: true` to `required: false` (line 398)
  - Update the flag description to note auto-detection when omitted

**Validation:**

- `pnpm --filter @warpgogol/forge run build:check` — typecheck passes

**Completion criterion:** The handler accepts calls without `--implementation-commit`; auto-detect runs when the flag is omitted; the flag still overrides when provided.

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Wrong commit auto-detected (earlier doc/plan commit references RFC ID) | Step 1 uses `--no-merges` and `--fixed-strings`; Step 3 tests verify the correct commit is picked when only one matches; RFC-IMP-03 reachability check still applies |
| Multiple commits found | Step 2 handles via RFC-IMP-03 violation listing candidates; Step 3 tests verify the error path |
| Auto-detect vs RFC-IMP-03 asymmetry (file-name-only refs) | Documented in RFC-0756 Failure modes section; auto-detect is convenience, not replacement for explicit flag |
| Stale command manifest | Step 4 regenerates manifest; validation checks `rfc.validate` passes with zero violations |

## 6. Escalation triggers

- If implementation reveals that `--fixed-strings` is not available in the git version used by CI, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0756 --reason "git --fixed-strings not available" --invariant "DNA-49"` instead of working around it.
- If auto-detect produces false positives at an unacceptable rate, consider reverting to `required: true` via a superseding RFC rather than adding heuristics to filter candidates.
