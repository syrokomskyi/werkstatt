### Step 1. Expand repo validation regex

**Goal:** Amend the `fleetRegistryEntrySchema` `repo` field to accept local file paths in addition to SSH/HTTPS git URLs.

**Agent actions:**

- In `packages/ontology/src/operations/sternsystem.ts`, update the `gitUrlRe` regex to accept:
  - SSH URLs: `git@github.com:org/repo.git`
  - HTTPS URLs: `https://github.com/org/repo.git`
  - Local relative paths: `../systems-git/warpgogol-com`, `./systems-git/warpgogol-com`
  - Local absolute paths: `/absolute/path/to/repo`
- The regex should reject empty strings and strings that look like neither a git URL nor a file path.
- Update the Zod error message from `"repo must be a valid git URL (SSH or HTTPS)"` to `"repo must be a valid git URL (SSH, HTTPS) or local file path"`.

**Validation:**

- `pnpm --filter @gogol/ontology run build:check` passes
- `pnpm --filter @gogol/ontology test` passes (if test suite exists)

**Completion criterion:** `fleetRegistryEntrySchema.parse({ repo: "../systems-git/warpgogol-com", ... })` succeeds without Zod error.

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Production outage from broken main deployment | Step 11 (alt-first gating) + Step 12 (main only after alt healthy). `leitstand.rollback` available at both steps. |
| Data loss during extraction | Step 8 validates with `sternsystem.validate`. Step 13 validates Notausgang export. Step 14 aborts if either fails. |
| Lock contention | Steps 7-10 acquire system lock. Only one operator runs the pilot. `werkstatt.lock.recover` for stale locks. |
| Wrangler auth missing | Step 11 requires `CLOUDFLARE_API_TOKEN` — preflight check fails before deploy, not mid-deploy. |
| Behavior snapshot mismatch | Step 10 `release.prepare` runs `behavior.snapshot.diff`. If it fails, the release stays `prepared` and is not published. |
| Agent re-creates `apps/warpgogol-com/` after removal | Step 15 `fleet.sites.generate` + `workspace.surface.validate` fail if `apps/` is referenced but does not exist. Step 17 AGENTS.md update removes stale guidance. |
| Precondition RFCs not yet implemented | Step 0 explicitly checks RFC-0378/0379/0380 status before any work begins. Aborts with actionable message if any is missing. |

## 6. Escalation triggers

- If `sternsystem.extract` reveals a data path that the current classifier misses (e.g., a new content directory not in the data-only partition), run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0381 --reason "extraction classifier misses <path>" --invariant "DNA-44"` instead of working around it.
- If `release.prepare` snapshot diff reveals a structural difference that cannot be resolved without changing the build pipeline, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0381 --reason "snapshot diff reveals structural mismatch" --invariant "DNA-48"`.
- If `leitstand.propagate` reveals an incompatibility between the RFC-0379 adapter contract and the actual Cloudflare Workers API, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0379 --reason "adapter contract mismatch" --invariant "DNA-49"`.
- If `notausgang.validate` reveals a Bordbuch or artifact integrity issue that requires contract changes, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0380 --reason "integrity verification gap" --invariant "DNA-50"`.
