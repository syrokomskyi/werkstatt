## 3. Step sequence

### Step 1. Profile schema extension — add `devServer` field

**Goal:** Add `profileDevServerSchema` to `profile-schema.ts` and wire it into `stackProfileDomainFieldsSchema` and `StackProfileDomainFields`. Add `devServer` to `stackProfileSchema` and `StackProfile` in `stack-profile.ts`.

**Agent actions:**

- Add `profileDevServerSchema` Zod schema with `command` (required string), `port` (optional positive int), `readinessTimeout` (optional positive int) to `profile-schema.ts`
- Add `ProfileDevServer` TypeScript interface
- Add `devServer: profileDevServerSchema.optional()` to `stackProfileDomainFieldsSchema`
- Add `devServer?: ProfileDevServer` to `StackProfileDomainFields`
- Add `devServer: stackProfileDomainFieldsSchema.shape.devServer` to `stackProfileSchema` in `stack-profile.ts`
- Add `devServer?: ProfileDevServer` to `StackProfile` interface (already extends `StackProfileDomainFields` so this is automatic)

**Validation:**

- `pnpm --filter @warpgogol/forge run build:check` — TypeScript compiles
- `pnpm exec werkstatt run forge.profile.validate` — existing profiles still validate (devServer is optional)

**Completion criterion:** `profileDevServerSchema` and `ProfileDevServer` exported from `profile-schema.ts`; `devServer` field present in `stackProfileDomainFieldsSchema` and `StackProfile`; `build:check` passes; `forge.profile.validate` passes.

**Human review:** no

---

### Step 2. Shared profile resolution logic

**Goal:** Create a shared `resolveActiveProfile` function that reads `forge.yaml`, resolves the active profile id, loads the profile YAML, and returns the `StackProfile` or exits with an error.

**Agent actions:**

- Create `packages/forge/os/core/handlers/profile-resolve.ts`
- Implement `resolveActiveProfile(workspaceRoot: string, forgeRoot: string, profileIdOverride?: string): StackProfile | null`
- Read `forge.yaml` for `profile` field, fall back to `project.stack[0]`
- Load profile YAML from `<forgeRoot>/profiles/<id>.yaml`
- Return `null` if no active profile or profile not found (caller handles error messaging)

**Validation:**

- `pnpm --filter @warpgogol/forge run build:check`

**Completion criterion:** `resolveActiveProfile` function exists and compiles; returns a loaded `StackProfile` or `null`.

**Human review:** no

---

### Step 3. Implement `forge.dev` handler

**Goal:** Create the `forge.dev` handler that resolves the active profile, reads `devServer`, and either prints the resolved command (`--dry-run`) or starts the dev server via `child_process.spawn`.

**Agent actions:**

- Create `packages/forge/os/core/handlers/dev.ts`
- Implement `runDev(input, context)` returning `ForgeCommandResult<ForgeDevResult>`
- Resolve active profile via `resolveActiveProfile`
- If no profile or no `devServer`, return exit 1 with error message
- If `--dry-run`, print resolved command, port, profile id — do not spawn
- If not dry-run, spawn the dev server command, stream stdout/stderr, handle SIGINT with exit code 130
- Support `--json` flag for structured output on exit

**Validation:**

- `pnpm --filter @warpgogol/forge run build:check`

**Completion criterion:** `runDev` handler exists, compiles, handles `--dry-run`, `--json`, `--profile` flags, and SIGINT exit code 130.

**Human review:** no

---

### Step 4. Implement `forge.build` handler

**Goal:** Create the `forge.build` handler that resolves the active profile, reads `artifacts`, and executes produce commands sequentially (or prints them with `--dry-run`).

**Agent actions:**

- Create `packages/forge/os/core/handlers/build.ts`
- Implement `runBuild(input, context)` returning `ForgeCommandResult<ForgeBuildResult>`
- Resolve active profile via `resolveActiveProfile`
- If no profile or no `artifacts`, return exit 1 with error message
- If `--dry-run`, print resolved produce commands — do not execute
- If not dry-run, execute each artifact's `produce.command` via `child_process.exec`, collect exit code, stdout, stderr
- Skip artifacts without `produce` command with a warning
- Support `--json` flag for structured output

**Validation:**

- `pnpm --filter @warpgogol/forge run build:check`

**Completion criterion:** `runBuild` handler exists, compiles, handles `--dry-run`, `--json`, `--profile` flags, executes produce commands, reports exit codes.

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Command injection via profile commands | Step 2: profiles are trusted files, `--dry-run` lets operator inspect commands before execution |
| Profile staleness (command renamed) | Steps 3-5: error messages include the resolved command and profile path for diagnosis |
| Long-running `forge dev` blocks | Step 3: SIGINT handling with exit code 130; `--dry-run` provides structured output without starting server |
| Multiple artifacts slow build | Step 4: sequential execution with per-artifact exit codes; `--dry-run` for quick inspection |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-54, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0674 --reason "..." --invariant "DNA-54"` instead of working around it.
