## 3. Step sequence

### Step 1. Implement CSP parser

**Goal:** Create the CSP directive parser that extracts `Map<directive, source[]>` from the `Content-Security-Policy` header value in `public/_headers`.

**Agent actions:**

- Create `packages/werkstatt-site/src/checks/csp-origins.ts`
- Implement `parseCsp(cspHeader: string): Map<string, string[]>` — splits by `;`, trims, extracts directive name + space-separated sources
- Implement `normalizeSource(source: string, siteOrigin: string): SourceMatcher` — handles `'self'` → site origin, `'none'` → empty set, `*.example.com` → wildcard subdomain matcher, `https://example.com` → exact origin, `'unsafe-inline'`/`'unsafe-eval'` → keyword token
- Implement `originMatchesSource(origin: string, sources: string[], siteOrigin: string): boolean` — checks if an origin is covered by any source in the directive (with `default-src` fallback)
- Reuse CSP extraction regex from `security.ts` (`/Content-Security-Policy:\s*(.+)$/im`)

**Validation:**

- `pnpm --filter @warpgogol/werkstatt-site run build:check` — TypeScript compiles

**Completion criterion:** `parseCsp` returns correct `Map<directive, source[]>` for sample CSP strings; `originMatchesSource` correctly matches `'self'`, exact origins, and wildcard subdomains.

**Human review:** no

---

### Step 2. Implement origin extraction from rendered HTML

**Goal:** Extract all external origins from `.html` files in `dist/client/` that require CSP coverage.

**Agent actions:**

- In `csp-origins.ts`, implement `extractOriginsFromHtml(html: string, filePath: string): ExtractedOrigin[]`
- Use `parse5.parse()` (already a dependency — see `strip-html-generated-marker.ts` for usage pattern) to parse HTML, then traverse the DOM tree for:
  - `<script src="...">` and `<script type="module" src="...">` → script origins (CSP-ORIGIN-01)
  - `<link rel="stylesheet" href="...">` → style origins (CSP-ORIGIN-02)
  - `<link rel="preload" as="script" href="...">` → script origins (CSP-ORIGIN-01)
  - `<img src="...">` and `<img srcset="...">` → image origins (CSP-ORIGIN-03)
  - `<source srcset="...">` in `<picture>` → image origins (CSP-ORIGIN-03)
  - Inline `<script>` blocks: regex for `fetch("...")` and `new URL("...")` patterns → connect origins (CSP-ORIGIN-04)
- Skip same-origin resources (starting with `/` or matching site origin)
- Skip `data:` URIs (covered by `data:` source in CSP)
- Wrap `parse5.parse()` in try/catch (per ADR-0018 finding — malformed HTML must not crash the validator)
- Implement `scanDistForOrigins(distDir: string): Promise<ExtractedOrigin[]>` — walks `dist/client/**/*.html`, calls `extractOriginsFromHtml` for each file

**Validation:**

- `pnpm --filter @warpgogol/werkstatt-site run build:check`

**Completion criterion:** `extractOriginsFromHtml` correctly extracts all external origins from a fixture HTML string; same-origin and `data:` URIs are skipped; malformed HTML does not throw.

**Human review:** no

### Step 3. Implement cross-referencing and command handler

**Goal:** Cross-reference extracted origins against CSP directives and produce findings.

**Agent actions:**

- In `csp-origins.ts`, implement `runCspOriginsValidate(input: KernelCommandInput, context: KernelRuntimeContext): Promise<KernelCommandResult<CheckResult>>`
- Load site context via `loadPublicContext(context)` (same pattern as `runHeadersSecurityValidate`)
- Read `public/_headers`, extract CSP header value
- Parse CSP into `Map<directive, source[]>`
- Scan `dist/client/**/*.html` for external origins
- For each extracted origin, check against the corresponding CSP directive (with `default-src` fallback):
  - Script origins → `script-src` (CSP-ORIGIN-01, severity: `error`)
  - Style origins → `style-src` (CSP-ORIGIN-02, severity: `error`)
  - Image origins → `img-src` (CSP-ORIGIN-03, severity: `warning`)
  - Connect origins → `connect-src` (CSP-ORIGIN-04, severity: `error`)
- Return `diagnosticsResult("csp.origins.validate", findings)` with `CspOriginResult` JSON shape
- Handle failure modes: missing `_headers` → skip pass, missing `dist/client/` → skip pass, empty `dist/client/` → skip pass, CSP not found → skip pass, malformed CSP → warning + skip directive

**Validation:**

- `pnpm --filter @warpgogol/werkstatt-site run build:check`

**Completion criterion:** `runCspOriginsValidate` produces correct findings for a fixture with a missing script origin; all failure modes return `status: "pass"` with appropriate skip behavior.

**Human review:** no

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| False positives from dynamically injected scripts | Step 2: only statically referenced origins in rendered HTML are scanned; dynamically injected scripts are out of scope by design |
| False positives from data-URI scripts | Step 2: `data:` URIs are explicitly skipped in origin extraction |
| CSP parsing complexity | Step 1: parser handles common cases, falls back to `warning` for unparseable directives; Step 6: tests cover edge cases |
| Agent confusion (adding wildcards to fix) | Step 3: `fixHint` in findings suggests the specific origin to add, not a wildcard |
| Malformed HTML crashing validator | Step 2: `parse5.parse()` wrapped in try/catch per ADR-0018 pattern |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-N, run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0831 --reason "..." --invariant "DNA-N"` instead of working around it.
- If `connect-src` scanning of bundled JS files becomes necessary (currently out of scope), create a follow-up RFC rather than expanding this one.
