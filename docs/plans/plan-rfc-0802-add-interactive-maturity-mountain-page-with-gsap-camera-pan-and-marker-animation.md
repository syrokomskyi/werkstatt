### Step 4. Implement GSAP script and client entry

**Goal:** Create `gsap-mountain-journey.ts` with MotionPathPlugin registration and form-triggered animation; wire up `.client.ts`.

**Agent actions:**

- Create `packages/werkstatt-site/src/domain/share/scripts/gsap-mountain-journey.ts`:
  - Export `initMountainJourneyAnimation(options: MountainJourneyAnimationOptions): Promise<void>`
  - Define constants: `CAMERA_INITIAL_ZOOM = 2.5`, `CAMERA_FINAL_ZOOM = 1.0`, `ANIMATION_DURATION = 3`
  - Dynamic `import("gsap")`, `import("gsap/ScrollTrigger")`, `import("gsap/MotionPathPlugin")`
  - Register both plugins
  - Check `prefers-reduced-motion` — if reduce, place marker directly at score position via `path.getPointAtLength()`
  - Add form submit listener: POST `{ url }` to `import.meta.env.PUBLIC_MOUNTAIN_JOURNEY_ENDPOINT`, parse `{ score: number }`
  - On success: create GSAP timeline with `motionPath` (marker along route to `score/100`) + `scale` (camera zoom out) running simultaneously
  - On error: show `errorMessage`, no animation
  - MotionPathPlugin import failure fallback: use `path.getPointAtLength()` for static placement
- Edit `mountain-journey-section.client.ts`:
  - DOM guard: check for `mountain-journey__scene` selector
  - Read `workerEndpoint` from `import.meta.env.PUBLIC_MOUNTAIN_JOURNEY_ENDPOINT`
  - Call `initMountainJourneyAnimation` with selectors and endpoint
  - Use `document.readyState` check pattern (same as `chat-widget-section.client.ts`)
- Commit via `ecosystem.commit`

**Validation:**

- `pnpm --filter @warpgogol/werkstatt-site exec tsc --noEmit` passes
- `gsap/MotionPathPlugin` import resolves (already in `node_modules/gsap/MotionPathPlugin.js`)

**Completion criterion:** GSAP script registers MotionPathPlugin, animates marker + camera on form submission, handles all failure modes (reduced-motion, no-JS, Worker error, plugin import failure).

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| section.scaffold stale paths | Step 0: fix paths before running scaffold (Step 2) |
| Bundle size impact (MotionPathPlugin ~5KB) | Step 4: dynamic import with DOM guard — only loaded on pages with `mountain-journey` section |
| Worker availability | Step 4: error handling in GSAP script — shows `errorMessage` on failure, no animation |
| SVG path coordinate drift | Step 6: `routePath` and `stages[].position` authored in block props, not hardcoded in component |
| Accessibility | Step 3: server-rendered static SVG, `<noscript>` message, DOM text labels; Step 7: verify reduced-motion and no-JS paths |
| LFS tracking gap | Step 5: add `.gitattributes` pattern before committing asset, verify with `git lfs ls-files` |
| Agent misinterpretation (scroll vs form trigger) | Step 4: form submit listener, not ScrollTrigger — distinct from RFC-0106 pattern |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-24 (block-declarative pages) or DNA-37 (SectionProps), run `pnpm exec werkstatt run rfc.supersede.propose --id RFC-0802 --reason "..." --invariant "DNA-N"` instead of working around it.
- If `section.scaffold` fails because the archetype YAML doesn't conform to `sectionArchetypeSchema`, fix the archetype YAML (Step 1) before re-running scaffold (Step 2).
- If `archetype.registry.build` fails to derive `Prometheus` in `PLANET_IMPORT_PATHS`, verify the manifest `cosmicName` field matches exactly.
- If `mission.open` fails with `--system` not found, verify the system id in `systems-cache/` directory.
