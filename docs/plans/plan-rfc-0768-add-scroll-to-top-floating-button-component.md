### Step 3. Create Mirror Quintet component files

**Goal:** Create all 5 Mirror Quintet files for the scroll-to-top component.

**Agent actions:**

- Create `packages/ui/src/components/scroll-to-top/scroll-to-top-component.manifest.yaml`:
  - `id: scroll-to-top-component`, `uniName: scroll-to-top-component`, `layer: component`, `semanticId: scroll-to-top`, `archetype: scroll-to-top`, `cosmicName: Daphnis`, `role: scroll-to-top`, `version: 1.0.0`, `intent: [guide-navigation, orient-visitor]`, `industryFit: []`, `contentSchemaKey: scroll-to-top-component`, `contentTypesPath: ./scroll-to-top-component.types.generated.ts`.
  - `propsSchema`: object with optional `ariaLabel: string`.
- Create `packages/ui/src/components/scroll-to-top/scroll-to-top-component.astro`:
  - Compass `MODULE_CONTRACT` and `CHANGE_SUMMARY` scaffolding.
  - Import `loadVendorIcon` from `../../icons/icon-resolver.ts`.
  - Load `ArrowUpHover` icon from `lordicon` / `doodle-outline` collection.
  - Render `<button>` with `data-scroll-to-top` attribute, `aria-label` prop with i18n fallback (de → "Nach oben", uk → "Догори", default → "Back to top").
  - LordIcon with `aria-hidden="true"`, `trigger="hover"`, `class="scroll-to-top__icon"`.
  - Inline `<script>` importing and initializing the client script.
  - Import `./scroll-to-top-component.css`.
- Create `packages/ui/src/components/scroll-to-top/scroll-to-top-component.css`:
  - `.scroll-to-top` fixed position, `bottom: var(--ds-space-4)`, `right: var(--ds-space-4)`, `z-index: 100`.
  - Size `48px x 48px`, `border-radius: var(--ds-radius-md)`.
  - Background `var(--ds-color-primary)`, color `var(--ds-color-text-inverse)`.
  - Hover background `var(--ds-color-secondary)`.
  - Default hidden: `opacity: 0`, `pointer-events: none`.
  - Visible class: `opacity: 1`, `pointer-events: auto`.
  - Transition: `opacity 0.3s ease, transform 0.3s ease`.
  - `@media print`: `display: none`.
  - `@media (prefers-reduced-motion: reduce)`: disable transitions.
- Create `packages/ui/src/components/scroll-to-top/scroll-to-top-component.client.ts`:
  - Compass `MODULE_CONTRACT` and `CHANGE_SUMMARY` scaffolding.
  - `initScrollToTop(button: HTMLElement)` function:
    - `prefersReducedMotion` via `window.matchMedia('(prefers-reduced-motion: reduce)')`.
    - Scroll listener with `requestAnimationFrame` throttling and `{ passive: true }`.
    - Visibility threshold: `window.scrollY > window.innerHeight` → toggle `scroll-to-top--visible` class.
    - Click handler: check `window.wgLenis` → `lenis.scrollTo(0, { immediate: prefersReducedMotion })` or `window.scrollTo({ top: 0, behavior: prefersReducedMotion ? 'auto' : 'smooth' })`.
    - LordIcon hover animation: on `mouseenter`, find `lord-icon` element, check `playerInstance`, call `playFromStart()` when `!playing` (following header-component pattern lines 472-496).

**Validation:**

- `rtk pnpm --filter @warpgogol/ui run build:check` — typecheck passes.

**Completion criterion:** All 4 authored files exist (manifest, .astro, .css, .client.ts) and typecheck passes.

**Human review:** no

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --------------- | ------------------------ |
| Performance: scroll listener on every scroll event | Step 3: `requestAnimationFrame` throttling and `{ passive: true }` in client script |
| Z-index conflicts | Step 7: document `z-index: 100` in `packages/ui/AGENTS.md` |
| Accessibility: keyboard access, aria-label | Step 3: `<button>` element, `aria-label` with i18n fallback, LordIcon `aria-hidden="true"` |
| Agent misinterpretation: per-site config | RFC nonGoals + implementation notes explicitly forbid; plan does not add any per-site config |
| CSS raw colors | Step 3: CSS uses only `--ds-*` tokens; Step 8: `tokens.ds.lint` / `tokens.colors.lint` verify |

## 6. Escalation triggers

- If implementation reveals an invariant conflict with DNA-N, run `rtk pnpm exec site-kernel run rfc.supersede.propose --id RFC-0768 --reason "..." --invariant "DNA-N"` instead of working around it.
