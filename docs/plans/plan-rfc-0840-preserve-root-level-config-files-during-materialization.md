**Key design decision (grilling session 2026-08-14):**

`OPERATOR_CONFIG_FILES` uses **paths**, not just filenames. This resolves the DNA-72 contradiction:

```ts
const OPERATOR_CONFIG_FILES = [
  ".lighthouse-budget-ignore",            // root-level
  "src/image-delivery.config.yaml",       // src-level (DNA-72 compliant)
];
```

- `.lighthouse-budget-ignore` — validator reads from root (`lighthouse.ts:491`), persist/restore from root.
- `image-delivery.config.yaml` — validator reads from `src/` (`image-delivery.ts:221`), persist/restore from `src/`. DNA-72 satisfied.
- `path.join(workpieceDir, entry)` works with subpaths — no copy-logic changes needed.
- Files remain untracked — DNA-44 data-only contract preserved.
- `STERNSYSTEM_DATA_PATHS` not touched.
- Removed from original RFC list: `live-video-manifest.generated.yaml` (generated by `build.prepare`, in `src/`) and `dns-records.yaml` (lives in cache clone, not workpiece).

## 3. Step sequence

### Step 1. Create `operator-config-files.ts` with constant and persist/restore functions

**Goal:** Implement the core persistence module following the `env-persist.ts` pattern.

**Agent actions:**

- Create `packages/werkstatt/src/mission/operator-config-files.ts`.
- Define `OPERATOR_CONFIG_FILES` constant with path-based entries: `[".lighthouse-budget-ignore", "src/image-delivery.config.yaml"]`.
- Implement `persistOperatorConfigFiles(workpieceDir, cacheCloneDir): Promise<OperatorConfigPersistResult>` — copies each file in `OPERATOR_CONFIG_FILES` from workpiece to cache clone if it exists. Uses `path.join(workpieceDir, entry)` where `entry` may contain subpaths (e.g. `src/image-delivery.config.yaml`). Non-fatal on failure (catch → skipped).
- Implement `restoreOperatorConfigFiles(cacheCloneDir, workpieceDir): Promise<OperatorConfigPersistResult>` — copies each file from cache clone to workpiece if it exists. Uses `path.join(cacheCloneDir, entry)`. Non-fatal on failure. Does NOT modify file contents (unlike env restoration which rewrites `PUBLIC_IMAGE_PROVIDER`).
- Ensure parent directories exist before writing (e.g. `src/` may not exist yet if restore runs before `build.prepare` — use `mkdir` with `recursive: true` on the parent directory).
- Export `OperatorConfigPersistResult` interface (`{ copied: string[], skipped: string[] }`).
- Add MODULE_CONTRACT and CHANGE_SUMMARY header comments.

**Validation:**

- `pnpm --filter @warpgogol/werkstatt run build:check` — TypeScript compiles.

**Completion criterion:** `operator-config-files.ts` exists, exports `OPERATOR_CONFIG_FILES`, `persistOperatorConfigFiles`, `restoreOperatorConfigFiles`, and `OperatorConfigPersistResult`. TypeScript compiles.

### Step 4. Implement `materialize.config.validate` check command

**Goal:** Workspace-scope validator that checks `OPERATOR_CONFIG_FILES` list stays in sync with reality.

**Agent actions:**

- Create `packages/werkstatt/src/mission/materialize-config-validate.ts`.
- Implement `runMaterializeConfigValidate(input, context)`:
  - **MAT-CONFIG-01 (warning):** Scan all active mission workpieces (`missions/*/workpiece/`) for operator-authored files at root level and in `src/` (top-level only, not recursive into `src/content/`, `src/components/`, `src/bordbuch/`, etc.) that are:
    - NOT in `OPERATOR_CONFIG_FILES`
    - NOT in `STERNSYSTEM_DATA_PATHS` directories (`src/content`, `public`, `provenance`)
    - NOT generated files (exclude `*.generated.yaml`, `*.generated.json`, `content-ref-index.generated.yaml`, `content.config.ts`)
    - NOT standard boilerplate (`.gitignore`, `package.json`, `astro.config.mjs`, `tsconfig.json`, `wrangler.jsonc`, `postcss.config.cjs`, `.env*`, `system.pin.json`, `.github/`)
    - NOT standard directories (`node_modules/`, `dist/`, `.astro/`, `.turbo/`, `.wrangler/`, `.cache/`, `.integrity/`, `.surface-cache/`, `.git/`) Emit warning for each unrecognized file.
  - **MAT-CONFIG-02 (error):** For each entry in `OPERATOR_CONFIG_FILES`, check if it exists in any cache clone (`systems-cache/*/`) or active workpiece (`missions/*/workpiece/`). If a file exists in NONE of them, emit error (dead entry).
- Register command in `packages/werkstatt/src/mission/mission.module.ts`:
  - `name: "materialize.config.validate"`
  - `scope: "workspace"`
  - `description: "Validate OPERATOR_CONFIG_FILES list is in sync with actual workpiece/cache clone files (RFC-0840)."`
  - `reads: ["missions/*/workpiece/*", "missions/*/workpiece/src/*", "systems-cache/*/"]`
- Add MODULE_CONTRACT and CHANGE_SUMMARY header comments.

**Validation:**

- `pnpm --filter @warpgogol/werkstatt run build:check`

**Completion criterion:** `materialize.config.validate` command registered in `mission.module.ts` with `scope: "workspace"`. Handler implemented with MAT-CONFIG-01 and MAT-CONFIG-02 rules. TypeScript compiles.

## 5. Risks and mitigation

| Risk (from RFC) | Mitigation (plan step) |
| --- | --- |
| Stale config files persist in cache clone indefinitely | Step 4 MAT-CONFIG-02 detects dead entries in `OPERATOR_CONFIG_FILES` |
| New file types require superseding RFC | Step 4 MAT-CONFIG-01 warns about unrecognized files in root and `src/`, prompting RFC consideration |
| `src/` directory may not exist during restore before `build.prepare` | Step 1 uses `mkdir { recursive: true }` on parent directories before writing |
| Path-based entries in `OPERATOR_CONFIG_FILES` could be confused with directory paths | Entries are file paths (with extensions), not directory paths — convention enforced by the explicit list |

## 6. Escalation triggers

- If implementation reveals that `src/image-delivery.config.yaml` restore fails because `build.prepare` overwrites `src/` after restore, move the restore call to after `build.prepare` instead of after `restoreEnvFilesFromCacheClone`. This is a plan-level adjustment, not a superseding RFC.
- If `materialize.config.validate` proves too noisy (false positives on MAT-CONFIG-01), adjust the exclusion list. Tuning the exclusion list does NOT require a superseding RFC.
- If a new operator config file is needed in a subdirectory of `src/` (e.g. `src/config/something.yaml`), add it to `OPERATOR_CONFIG_FILES` via a superseding RFC.
