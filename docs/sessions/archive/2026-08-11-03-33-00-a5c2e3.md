### Assistant [2026-08-11T03:33:30+02:00]

Investigated the growth adapter loading mechanism in provider.astro and client.ts. Found root cause: the matomo adapter loader used /* @vite-ignore */ with a variable specifier (_adapterSpecifiers["matomo"]), which tells Vite not to bundle the import. The bare module specifier '@warpgogol/werkstatt-site/growth-adapter-matomo' is then passed as-is to the browser, which cannot resolve it without an import map or node_modules. The architecture comment in client.ts:40-44 explicitly says the host should use STATIC import() specifiers so the bundler code-splits each adapter into a resolvable async chunk. Fix: replaced the variable specifier + @vite-ignore with a static import() call.
